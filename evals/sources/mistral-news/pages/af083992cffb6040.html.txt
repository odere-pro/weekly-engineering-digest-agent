                <p class="text-body-large text-text-primary mb-10"></p>
                <h2
                  class="text-h3 font-mistral text-current mb-5 pb-5 border-b border-border-primary not-first:mt-16"
                >
                  Govern which tools run where, connect more than one account to a single connector,
                  and trace any connection that breaks.
                </h2>
                <p class="text-body-large text-text-primary mb-10"></p>
                <p class="text-body-large text-text-primary mb-10">
                  Today, we are introducing several new capabilities in Connectors for a more secure
                  experience integrating to external enterprise platforms. Starting now, you can
                  use:
                </p>
                <p class="text-body-large text-text-primary mb-10"></p>
                <ul class="mb-10 pl-5 flex flex-col gap-2 list-disc">
                  <li>
                    <p class="text-body-large text-current">
                      <strong>Enriched admin controls</strong> (GA) to set connector access per
                      workspace and switch individual tools on or off across an org or workspace
                    </p>
                  </li>
                  <li>
                    <p class="text-body-large text-current">
                      <strong>API keys with connector scopes</strong> (GA) to prevent impersonation
                      in automated AI workloads that integrate with 3rd-party systems
                    </p>
                  </li>
                  <li>
                    <p class="text-body-large text-current">
                      <strong>Multi-account connectors</strong> (GA) allowing users to authenticate
                      to a single connector with multiple accounts
                    </p>
                  </li>
                  <li>
                    <p class="text-body-large text-current">
                      <strong>Connectors Debugger</strong> (Public Preview) for end-to-end root
                      cause analysis for MCP connectors
                    </p>
                  </li>
                  <li>
                    <p class="text-body-large text-current">
                      <strong>Connectors in Vibe Code</strong> (GA) to reuse your connectors in
                      developer interfaces
                    </p>
                  </li>
                  <li>
                    <p class="text-body-large text-current">
                      <strong>Connectors in Workflows</strong> (Public Preview) allow for
                      uninterrupted long-running tasks powered by all the tools you need
                    </p>
                  </li>
                </ul>
                <p class="text-body-large text-text-primary mb-10">
                  Async agents are moving into everyday work. For an agent to be trustworthy and
                  useful inside an organization, it needs real enterprise data: CRM records,
                  repositories, inboxes, knowledge bases. Connecting an agent to that data in a demo
                  is easy. Running it in production is where most setups stall.
                </p>
                <p class="text-body-large text-text-primary mb-10">
                  Production connectivity has a few non-negotiables. A connector should respect two
                  sets of rules at once: the permissions already set in the source platform, and the
                  controls your administrators set in Mistral Studio or Vibe. Automated work should
                  run on behalf of a user or a service account, never impersonate the person who
                  wrote it. When a connection breaks, you should be able to find out why. And an
                  administrator should be able to decide, down to the individual tool, what is
                  available in each part of the organization.
                </p>
                <p class="text-body-large text-text-primary mb-10"></p>
                <h2
                  class="text-h3 font-mistral text-current mb-5 pb-5 border-b border-border-primary not-first:mt-16"
                >
                  More control over what connectors can do
                </h2>
                <p class="text-body-large text-text-primary mb-10">
                  <strong>Enriched admin controls</strong> work at two levels: across your teams,
                  and inside each connector.
                </p>
                <ul class="mb-10 pl-5 flex flex-col gap-2 list-disc">
                  <li>
                    <p class="text-body-large text-current">
                      <strong>Workspace and org controls</strong> let you give each team its own
                      connector access. Your finance workspace can reach internal data sources with
                      no open web access, while engineering gets developer tools and the internet.
                      Same directory, different rules per team. 
                    </p>
                  </li>
                  <li>
                    <p class="text-body-large text-current">
                      <strong>Tool-level controls</strong> go a step deeper. Inside any connector,
                      turn individual tools on or off for a whole org or one workspace. Block
                      anything that writes data, or one specific action like
                      <code
                        class="bg-surface-brand-secondary border border-border-primary rounded-sm px-2 py-px text-text-brand-8 dark:text-text-brand-7 text-base"
                        >delete_file</code
                      >
                      on a knowledge base. The connector stays connected; only the tools you approve
                      can run.
                    </p>
                  </li>
                </ul>
                <p class="text-body-large text-text-primary mb-10"></p>

                <p class="text-body-large text-text-primary mb-10"></p>
                <p class="text-body-large text-text-primary mb-10">
                  <strong>API keys with connector scope</strong> handle identity. When you create a
                  key, you choose whether it reaches only a workspace&#39;s shared connectors or
                  your private ones too, so an automated job runs with exactly the access it needs.
                  Paired with service accounts, automated work runs as a defined identity, never as
                  the person who wrote it.
                </p>
                <p class="text-body-large text-text-primary mb-10">
                  <strong>Multi-account connectors</strong> let one connector hold more than one
                  login. Connect a personal and a work account to the same connector, set a default,
                  and switch between them per task. Each account is stored and refreshed on its own,
                  so an agent acts in the right one without you standing up a second connector.
                </p>
                <p class="text-body-large text-text-primary mb-10"></p>
                <h2
                  class="text-h3 font-mistral text-current mb-5 pb-5 border-b border-border-primary not-first:mt-16"
                >
                  See why a connection fails
                </h2>
                <p class="text-body-large text-text-primary mb-10">
                  <strong>Connectors Debugger</strong>  tells you exactly where a connection breaks.
                  Point it at an MCP server URL, add OAuth credentials if the server needs them, and
                  run the check. It walks the connection through 11 steps, from reaching the server
                  to opening the MCP session, and logs each one. A failure that used to mean
                  guesswork, like a broken OAuth token exchange, shows up at the exact step it
                  happens.
                </p>

                <h2
                  class="text-h3 font-mistral text-current mb-5 pb-5 border-b border-border-primary not-first:mt-16"
                >
                  <strong>Connectors </strong>in Workflows and Vibe for Code
                </h2>
                <p class="text-body-large text-text-primary mb-10">
                  <strong>Connectors in Workflows </strong>keep long and scheduled runs from
                  breaking on auth. You declare the connectors a Workflow needs, and the accounts it
                  should run with, right in the Workflow definition; Studio resolves those
                  dependencies when you start a run. Personal credentials stay out of automated
                  work, and a job won&#39;t fail halfway because a token expired. A nightly run can
                  pull from a CRM, update a tracker, and read a knowledge base across the whole job
                  without dropping a connection.
                </p>

                  <strong>Connectors in Vibe Code</strong> bring the same governed access to the
                  coding agent. Type
                  <code
                    class="bg-surface-brand-secondary border border-border-primary rounded-sm px-2 py-px text-text-brand-8 dark:text-text-brand-7 text-base"
                    >/connectors</code
                  >
                  to pick from local MCP servers and the workspace connectors your admins approved,
                  choose which tools to enable, and start a task. Async agents can reach Outlook,
                  Jira, Notion, Linear, and Confluence under the same rules you set everywhere else.
                </p>

                  connector fills the gap.
