<p><!--[--><!--[0--><div class="absolute -left-12 bottom-0 top-0 z-30 not-prose hidden lg:block"><div class="sticky top-4 flex"><div class="h-7 pt-[0.175rem]"><span class="peer" tabindex="0"><button class="select-none text-gray-400 hover:cursor-pointer hover:text-gray-800 dark:text-gray-500 dark:hover:text-gray-400"> <!----></button></span> <div class="invisible w-0 -translate-x-8 -translate-y-6 overflow-hidden rounded-xl border bg-white transition-transform hover:visible hover:w-52 hover:translate-x-0 peer-focus-within:visible peer-focus-within:w-52 peer-focus-within:translate-x-0"> </div></div></div></div><!--]--><!--]-->Muse Spark Open is an open-weight model from Meta. The mixture of experts model brings text, images, audio, and video into a model with approximately 816 billion parameters, around 42 billion active per token, and a context window of up to one million tokens. It generates text, giving developers a common interface for asking questions about different kinds of input.</p>
<p>Following Muse Glimmer, Muse Spark Open introduces a mixture-of-experts architecture at a much larger scale, and the most capable US open-weights model to date.</p>
<p>Meta trained Muse Spark Open for agentic coding: reading a codebase, writing and debugging code, and calling tools. It also takes images, audio, and video as input, so the same model can read a screenshot, listen to a voice note, or watch a screen recording while it works on your code. This post shows you how to run it, how to fine-tune it, and what we built with it. Find all the models <a href="https://huggingface.co/collections/meta-models/muse-spark-open">here</a>.</p>

<p>Muse Spark Open is the full-size model of the Muse series of models. Muse Glimmer, which Meta released in August, is a small dense model from the same series, ideal for running locally. Both models use the same tokenizer and vocabulary. The chat template follows the Muse Glimmer template, with additions for the new modalities. In Muse Spark Open the input embedding and the output layer are separate matrices of about 1.66B parameters each.</p>
<h3 class="relative group flex items-baseline">
	<a id="mixture-of-experts" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#mixture-of-experts" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Mixture of Experts
	</span>
</h3>
<p>The language model has 62 layers and a hidden dimension of 8192. Each layer has 128 query heads and 16 key-value heads (grouped-query attention). Each head has 64 dimensions. The attention block has an output gate and an output normalization layer. The model also applies normalization to the queries and the keys (QK-norm). Each block combines its input and its output through a learned residual gate, not through a plain sum.</p>
<p>Muse Glimmer uses one dense feed-forward network in each layer. Muse Spark Open replaces this dense network with a Mixture-of-Experts (MoE) block. Each MoE block has 256 experts, and a router selects 8 experts for each token. Each expert is a feed-forward network that projects from 8192 to 4096 dimensions and back to 8192, then applies its own normalization to its output. The experts hold ~97% of the total model parameters.</p>
<p>Only 8 experts run per token, so the model computes each token with about 42B parameters. All 256 experts stay in memory, so deployment needs the memory of an 816B-parameter model, but runs at the much faster speed of a 42B model. The BF16 checkpoint is about 1.5 TB in safetensors format. The NVFP4 checkpoint stores the parameters in 4-bit precision with negligible loss in accuracy, specifically for NVIDIA Blackwell GPUs. In transformers, the BF16 checkpoint runs across 4 nodes of 8 H200 GPUs with tensor parallelism (TP=32) and the NVFP4 runs on a single B200 node. If you want to deploy Muse Spark Open, check out the <code>llama.cpp</code>, vLLM, and SGLang recipes below.</p>
<h3 class="relative group flex items-baseline">
	<a id="perception-encoder" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#perception-encoder" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Perception Encoder
	</span>
</h3>
<p>A perception encoder converts images and video frames into tokens for the language model, just like Muse Glimmer. The encoder has 1.8B parameters, 50 layers, a hidden dimension of 1536, and 16 attention heads. It splits each image into 14×14 patches and produces features with 4096 dimensions. Position information comes from learned absolute embeddings and 2D RoPE. The feed-forward network in each layer uses LayerNorm and GELU. Every fourth layer and the last layer use full attention, and the other layers use sparse attention.</p>
<p><a href="https://huggingface.co/datasets/merve/meta-muse-spark-open-assets/resolve/main/image_pipeline.png" rel="nofollow"><img src="https://huggingface.co/datasets/merve/meta-muse-spark-open-assets/resolve/main/image_pipeline.png" alt="image pipeline diagram"></a></p>
<p>Muse Glimmer 30B uses an encoder with the same architecture. The design follows the  <a href="https://huggingface.co/papers/2504.13181">Perception Encoder</a> work from Meta. Video input goes through the same encoder as images.</p>
<h3 class="relative group flex items-baseline">
	<a id="audio-encoder" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#audio-encoder" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Audio Encoder
	</span>
</h3>
<p><a href="https://huggingface.co/datasets/merve/meta-muse-spark-open-assets/resolve/main/audio_encoder.png" rel="nofollow"><img src="https://huggingface.co/datasets/merve/meta-muse-spark-open-assets/resolve/main/audio_encoder.png" alt="audio diagram"></a></p>
<p>Muse Spark Open accepts audio as input through its audio encoder. An audio tokenizer converts the audio into tokens, and the chat template marks the audio position with <code>&lt;|audio|&gt;</code> tokens. The encoder emits one audio token every 80 ms, which yields 12.5 tokens per second. So let’s say, you have an audio of 10 seconds, the number of input audio tokens would be 125.
The encoder itself is a convolutional pyramid where each stage consists of a patch embedder of different patch sizes and 2 convolutional blocks of 1d kernels of size 7 with stride of 1. These stages are repeated for patch sizes of [16, 6, 5, 4]. At the end of the final stage, the temporal frames are fed to a final block of RMSNorm → linear projection → RMSNorm.</p>
<h3 class="relative group flex items-baseline">
	<a id="long-context" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#long-context" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Long Context
	</span>
</h3>
<p>The context window is 1M tokens at inference. The configuration sets <code>max_position_embeddings</code> to 1,048,576. This includes image, video, and audio tokens in the same window as text. </p>
<p>Grouped-query attention keeps the KV cache small for a model of this size. Each token adds 2 × 16 heads × 64 dimensions × 62 layers = 126,976 values to the cache. In BF16, this is about 250 KB per token and about 266 GB for a full 1M-token context.</p>

<h3 class="relative group flex items-baseline">
	<a id="transformers" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#transformers" rel="nofollow">

	</span>
</h3>
<p>The Muse Spark Open implementation provides <code>MuseSparkForConditionalGeneration</code> for text generation from multimodal inputs and <code>MuseSparkProcessor</code> for preparing conversations. <h4 class="relative group flex items-baseline">
	<a id="video-inference" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#video-inference" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Video Inference
	</span>
</h4>
<p>Video prompts include frame timing as well as visual content. The processor handles videos with audios in them (which is an upgrade from Muse Glimmer thanks to the audio encoder). The processor downsamples video frames and audio to align frames together. By default, videos are sampled to 2 FPS, capped at 96 frames. You can modify this by setting the fps of the video processor:</p>
<pre><code>processor.video_processor.fps = 4.0
</code></pre>
<p>As a general rule of thumb, videos are frames in temporal sequence, and the more you downsample, the more you will lose frames in between specific events, so you need to keep fps high if you want more accurate generations. However, there’s a trade-off because you will require more memory and increase latency for prefill. The frames are interleaved with text input that states timestamps (e.g. “Time: 3.5s”). To enable passing in videos with audio, pass <code>load_audio_from_video=True</code> to <code>apply_chat_template</code>.</p>
<p>Preserve the video's metadata when preparing inputs with <code>return_metadata=True</code> so the processor can assign the correct framerate.</p>
<pre><code class="language-py"><span class="hljs-keyword">import</span> torch

<h3 class="relative group flex items-baseline">
	<a id="audio-inference" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#audio-inference" rel="nofollow">

	</a>
	<span>
		Audio Inference
	</span>
</h3>
<p>The Muse Spark Open audio tower consumes a raw waveform. The processor expects mono audio at 24 kHz and pads the waveform to a multiple of 1,920 samples, corresponding to one audio embedding per 80 milliseconds. Audio supplied directly to the processor at another sample rate must first be resampled. You can do this by using the <code>load_audio</code> util of transformers. <code>load_audio</code> uses torchcodec, librosa or torchaudio backends, so make sure to have one of these installed locally before running inference.</p>
<p>If you want to simply use <code>apply_chat_template</code> with messages though, this is all handled for you under the hood:</p>

).to(model.device).to(model.dtype)

input_len = inputs[<span class="hljs-string">"input_ids"</span>].shape[-<span class="hljs-number">1</span>]
outputs = model.generate(**inputs)
response = processor.parse_response(
      completion,
      prefix=inputs[<span class="hljs-string">"input_ids"</span>][<span class="hljs-number">0</span>],
      tools=tools,
  )
<span class="hljs-built_in">print</span>(response)
</code></pre>
<p>Muse Spark Open uses a channel-based chat template (Harmony, first introduced by gpt-oss). Note that you don’t have to know about the internals, but it’s useful to check the channels the model routes to, in case you get low quality outputs. In the input message below:</p>
<pre><code>&lt;|begin_of_text|&gt;
  &lt;|start|&gt;system&lt;|message|&gt;
  You are a helpful AI assistant.
  Knowledge cutoff: 2026-01-04.
  Current date: ...
  ...
  &lt;|eot|&gt;
  &lt;|start|&gt;user&lt;|message|&gt;...
  &lt;|eot|&gt;
  &lt;|start|&gt;assistant
</code></pre>
<p><code>&lt;|start|&gt;assistant</code> is intentionally left open, it’s the model that chooses recipient with <code>to=</code> . The model has different recipients, e.g. <code>self</code> asks the model to reason, </p>
<pre><code>to=self&lt;|message|&gt;the model reasons here&lt;|eom|&gt; # reasoning
&lt;|start|&gt;assistant to=user&lt;|message|&gt;final answer&lt;|eot|&gt; # final answer
</code></pre>
<p><code>self</code> is for reasoning, <code>commentary</code> are comments before and between tool calls visible to the end user, <code>user</code> is the final response.<br>Tool-call routing is parsed as follows (assuming you have passed <code>tools</code> to <code>apply_chat_template</code>:</p>
<pre><code>&lt;|start|&gt;assistant to=weather.get&lt;|message|&gt;
  &lt;atem:function_calls&gt;
  &lt;atem:invoke name="weather.get"&gt;
  &lt;atem:parameter name="city"&gt;San Francisco&lt;/atem:parameter&gt;
  &lt;/atem:invoke&gt;
  &lt;/atem:function_calls&gt;
  &lt;|eot|&gt;
</code></pre>
<h3 class="relative group flex items-baseline">
	<a id="llamacpp" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#llamacpp" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Llama.cpp
	</span>
</h3>
<p><video controls="" width="720"> <source src="https://huggingface.co/datasets/merve/meta-muse-spark-open-assets/resolve/main/webui.mp4" type="video/mp4"> </video> </p><p><small>Muse Spark 2-bit running on Llama Server</small></p><p></p>
<p>Muse Spark Open is integrated in llama.cpp and comes in the prebuilt binaries. You can install this with following command:</p>
<pre><code>curl -LsSf https://llama.app/install.sh | sh
</code></pre>
<p>You can start the server as follows with quant suffix attached to model ID:</p>
<pre><code>
llama serve -hf ggml-org/Muse-Spark-Open-816B-A42B-GGUF:Q2_K
</code></pre>
<p>The repository containing quants is <a href="https://huggingface.co/ggml-orgf/Muse-Spark-Open-816B-A42B-GGUF">here</a>. Once the server has started, you can head to localhost:9931 to chat with the built-in WebUI. From the web UI you can add audio and images for inference and adjust the reasoning lever.<br>Note that turning off reasoning is not possible with Muse Spark Open, so keep the model reasoning at “low” if you want to consume less tokens to solve an easier task.<br>We tested quants on Mac M3 Ultra (512GB). An imatrix-calibrated 2-bit quant runs at 18 tokens/s, with plenty of room free for the KV cache (304 GB used by the model). </p>
<p>You can also query the server as follows. Feel free to check out <a href="https://llama.app/docs/serve" rel="nofollow">the API reference</a> for multimodality, tool calls and more. </p>
<pre><code>## Text-only inference
curl http://localhost:8080/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
        "messages": [
            {"role": "system", "content": "You are a helpful assistant."},
            {"role": "user", "content": "Write a limerick about python exceptions"}
        ]
    }'

## Image-text inference
curl -s http://127.0.0.1:8080/v1/chat/completions \
  -H "Content-Type: application/json" -H "Authorization: Bearer &lt;your-key&gt;" \
  -d '{"model":"muse-spark-open","messages":[{"role":"user","content":[
        {"type":"text","text":"What is in this image?"},
        {"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}
      ]}],"temperature":0}'

## Audio-text inference
curl -s http://127.0.0.1:8080/v1/chat/completions \
  -H "Content-Type: application/json" -H "Authorization: Bearer &lt;your-key&gt;" \
  -d '{"model":"muse-spark-open","messages":[{"role":"user","content":[
        {"type":"text","text":"Transcribe this audio."},
        {"type":"input_audio","input_audio":{"data":"data:audio/wav;base64,..."}}
      ]}],"temperature":0}'
</code></pre>
<p>llama.cpp team ships different quantized versions. We have tested Q2_K, Q4_K_S and Q_8 on Apple Silicon chips. You can run each quant by adding the quant id as suffix, <code>llama serve -hf ggml-org/Muse-Spark-Open-816B-A42B:Q2_K</code>.</p>

	</span>
</h3>
<p>The Muse Spark Open integration for SGLang supports text, image, audio, and video inputs. The NVFP4 reference configuration runs across four GB300 GPUs.</p>
<p>From the SGLang integration environment, download the checkpoint from the Hugging Face Hub and start the server:</p>
<pre><code>export MODEL_ID=meta-models/Muse-Spark-Open-816B-A42B-NVFP4

  --ep-size 4 \
  --port 30000
</code></pre>
<p>The checkpoint includes the chat template, which we pass explicitly. The launcher configures the Muse reasoning and tool-call parsers.</p>
<p>Send a request through the OpenAI-compatible API:</p>
<pre><code>curl http://localhost:30000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "meta-models/Muse-Spark-Open-816B-A42B-NVFP4",

      "role": "user",

    "max_tokens": 2048
  }'
</code></pre>

<h3 class="relative group flex items-baseline">
	<a id="vllm" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#vllm" rel="nofollow">

	</span>
</h3>
<p>The Muse Spark Open reference integration for vLLM supports text and image inputs with the NVFP4 checkpoint that require blackwell series GPUs.</p>
<p>After installing the reference plugin and its dependencies, download the checkpoint from the Hugging Face Hub and launch the server:</p>
<pre><code>export MODEL_ID=meta-models/Muse-Spark-Open-816B-A42B-NVFP4

VLLM_ALLOW_LONG_MAX_MODEL_LEN=1 \

  --served-model-name "$MODEL_ID" \
  --tokenizer-mode musespark1x \
  --config-format auto \
  --load-format internal_safetensor \
  --tensor-parallel-size 4 \
  --enable-expert-parallel \
  --max-model-len 131072 \
  --gpu-memory-utilization 0.92 \
  --reasoning-parser musespark1x \
  --tool-call-parser musespark1x \
  --enable-auto-tool-choice \
  --port 8000
</code></pre>
<p>This configuration sets a 128K-token serving context. The plugin supplies the model implementation, checkpoint loader, and reasoning and tool-call parsers.</p>
<p>Send a request using the same Hub model ID:</p>
<pre><code>curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \

    "model": "meta-models/Muse-Spark-Open-816B-A42B-NVFP4",

<h2 class="relative group flex items-baseline">
	<a id="mlx" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#mlx" rel="nofollow">
		<span class="header-link"> </span>

	<span>
		MLX

<p>Muse Spark Open is available in <a href="https://github.com/jundot/omlx" rel="nofollow">oMLX</a> and <a href="https://github.com/ml-explore/mlx-lm" rel="nofollow">mlx-lm</a> today. oQ quants optimized for oMLX are available in <a href="https://huggingface.co/mlx-community/Muse-Spark-Open-816B-A42B-oQ3e">3-bit</a> and <a href="https://huggingface.co/mlx-community/Muse-Spark-Open-816B-A42B-oQ4e">4-bit</a>, ready to use right away.</p>
<p>We tested the oQ3e quant on an M3 Ultra (512 GB). The model takes about 344 GB, leaving room for the KV cache, and runs at about 225 tok/s prefill and 21 tok/s generation with a 1024-token prompt and 128 generated tokens.</p>
<p>Once you download the model through the oMLX interface, you can chat with it in the built-in chat UI. <p>Note that it's not possible to turn reasoning off, and the default (Auto) uses xhigh. Set it to “low” if you want to use fewer tokens on easier tasks.

<pre><code>mlx_lm.generate --model mlx-community/Muse-Spark-Open-816B-A42B-oQ3e \
  --prompt "Explain convolutional networks like I am 5" \
  --max-tokens 5000
</code></pre>
<p>This is a big model, even the 3-bit quantization requires more than 256 GB of RAM, as explained above. You can also run distributed inference across multiple computers, please refer to the documentation for details.</p>

<h2 class="relative group flex items-baseline">
	<a id="fine-tuning-with-trl" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#fine-tuning-with-trl" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Fine-tuning with TRL
	</span>
</h2>
<p>You can fine-tune the 816B checkpoint with the TRL <code>SFTTrainer</code>. This section shows how we fine-tuned it with TRL on 8 nodes of 8 H100 GPUs. The recipe trains LoRA adapters on the attention layers. The experts stay frozen. The full script is in the <a href="https://github.com/huggingface/trl/tree/main/examples/sft_muse_spark_open" rel="nofollow">TRL examples</a>.</p>
<p>First, we need to split the model across 64 GPU devices. Given the large size of the model, we need to parallelize it across multiple axes. We shard the model with FSDP and split the experts across GPUs, using <code>DistributedConfig</code>, which tells <code>transformers</code> how to split the model when it loads:</p>
<pre><code class="language-py"><span class="hljs-keyword">from</span> transformers.distributed <span class="hljs-keyword">import</span> DistributedConfig

distributed_config = DistributedConfig(fsdp_size=<span class="hljs-number">64</span>, ep_size=<span class="hljs-number">8</span>)
</code></pre>
<p>In the snippet above, <code>fsdp_size=64</code> shards the model across all 64 GPUs with FSDP2, and <code>ep_size=8</code> splits the 256 experts of each layer into 8 groups. Transformers sends each token to the GPU that holds its expert, so each GPU trains on its own slice of the batch.</p>
<p>Now, we can configure the <code>SFTConfig</code> for our training run. We’ve performed a simple task here to adapt the model’s chat template on an open source dataset, but you could apply it to your own use case.</p>
<pre><code class="language-py"><span class="hljs-keyword">import</span> torch
<span class="hljs-keyword">from</span> datasets <span class="hljs-keyword">import</span> load_dataset
<span class="hljs-keyword">from</span> peft <span class="hljs-keyword">import</span> LoraConfig
<span class="hljs-keyword">from</span> transformers.distributed <span class="hljs-keyword">import</span> DistributedConfig
<span class="hljs-keyword">from</span> trl <span class="hljs-keyword">import</span> SFTConfig, SFTTrainer

train_dataset = load_dataset(<span class="hljs-string">"allenai/tulu-3-sft-mixture"</span>, split=<span class="hljs-string">"train[:500000]"</span>)

training_args = SFTConfig(
    output_dir=<span class="hljs-string">"muse-spark-lora-sft"</span>,
    model_init_kwargs={<span class="hljs-string">"dtype"</span>: torch.bfloat16, <span class="hljs-string">"distributed_config"</span>: DistributedConfig(fsdp_size=<span class="hljs-number">64</span>, ep_size=<span class="hljs-number">8</span>)},
    per_device_train_batch_size=<span class="hljs-number">1</span>,
    max_steps=<span class="hljs-number">500</span>,
    max_length=<span class="hljs-number">2048</span>,
    packing=<span class="hljs-literal">True</span>,
    save_only_model=<span class="hljs-literal">True</span>,
    logging_steps=<span class="hljs-number">1</span>,
    report_to=<span class="hljs-string">"trackio"</span>,
)

trainer = SFTTrainer(
    model=<span class="hljs-string">"meta-models/Muse-Spark-Open-816B-A42B"</span>,
    args=training_args,
    train_dataset=train_dataset,
    peft_config=LoraConfig(r=<span class="hljs-number">16</span>, lora_alpha=<span class="hljs-number">32</span>, target_modules=[<span class="hljs-string">"q_proj"</span>, <span class="hljs-string">"k_proj"</span>, <span class="hljs-string">"v_proj"</span>, <span class="hljs-string">"o_proj"</span>]),
)
trainer.train()
</code></pre>
<p>The core parts here are <code>packing=True</code> which joins examples into 2048-token sequences without padding. A block-diagonal mask keeps the examples separate. <code>save_only_model=True</code> saves the adapter and no optimizer state, because the trainer cannot resume a model that was sharded at load time. <code>LoraConfig</code> targets the four attention projections and the 256 experts of each layer stay frozen.</p>
<p>Then we can run this command across each node:</p>
<pre><code class="language-sh">torchrun --nnodes 8 --nproc_per_node 8 --rdzv_backend c10d --rdzv_endpoint <span class="hljs-string">"<span class="hljs-variable">$MASTER_IP</span>:29700"</span> sft_muse_spark_open.py
</code></pre>
<p>We trained for 500 steps, which took about 2 hours on 64 H100s, at about 8,000 tokens per second. Mean token accuracy rose from 72% to 84% and the loss fell from 1.26 to 0.57, which signals a good fine-tuning run.</p>

<h3 class="relative group flex items-baseline">

<p>Finally, we wanted to push Spark’s agentic multimodality to the limits, so we set up <a href="https://huggingface.co/spaces/burtenshaw/muse-spark-call-your-browser">this space</a> that combines the model’s audio, image, and agentic properties into a browser agent. We give the model a general description of a thing we need and it interacts with the integrated browser to find options on Amazon. </p>
<p><video controls="" width="720"> <source src="https://huggingface.co/buckets/huggingface/muse-spark-blog-assets/resolve/browser.mp4" type="video/mp4"> </video></p>
<p>Muse Spark Open takes the voice input and reasons over the type of product that meets the descriptions, searches for it on Amazon, and selects the most appropriate based on criteria. </p>

		<span class="header-link"> </span>
	</a>
	<span>
		Wrapping Up
	</span>
</h2>
<p>Muse Spark Open is a full-size open-weight model from the Muse series. Start with the <a href="https://huggingface.co/meta-models/Muse-Spark-Open-816B-A42B">BF16</a> or <a href="https://huggingface.co/meta-models/Muse-Spark-Open-816B-A42B-NVFP4">NVFP4</a> checkpoint, or try one of the great <code>llama.cpp quants</code>. If you build something with Muse Spark Open, share it, and tell us in the <a href="https://huggingface.co/meta-models/Muse-Spark-Open-816B-A42B/discussions">repository’s discussions.</a></p>
