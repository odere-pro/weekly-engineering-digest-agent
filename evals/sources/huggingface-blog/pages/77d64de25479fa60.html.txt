<p><!--[--><!--[0--><div class="absolute -left-12 bottom-0 top-0 z-30 not-prose hidden lg:block"><div class="sticky top-4 flex"><div class="h-7 pt-[0.175rem]"><span class="peer" tabindex="0"><button class="select-none text-gray-400 hover:cursor-pointer hover:text-gray-800 dark:text-gray-500 dark:hover:text-gray-400"> <!----></button></span> <div class="invisible w-0 -translate-x-8 -translate-y-6 overflow-hidden rounded-xl border bg-white transition-transform hover:visible hover:w-52 hover:translate-x-0 peer-focus-within:visible peer-focus-within:w-52 peer-focus-within:translate-x-0"> </div></div></div></div><!--]--><!--]-->Today, we’re excited to announce a deep-link integration between <a href="https://huggingface.co/">Hugging Face</a> and <a href="https://aws.amazon.com/sagemaker/ai/studio/" rel="nofollow">Amazon SageMaker AI</a>. Developers can now go from model discovery to hands-on experimentation in SageMaker Studio with a single selection. Whether you fine-tune a foundation model (FM) from <a href="https://aws.amazon.com/sagemaker/ai/jumpstart/" rel="nofollow">Amazon SageMaker JumpStart</a> or deploy it to an <a href="https://aws.amazon.com/sagemaker/ai/deploy/" rel="nofollow">Amazon SageMaker Inference</a> endpoint, you can now land directly inside the relevant SageMaker Studio workflow. Your selected model is pre-loaded, and the environment is fully configured and ready to go.</p>
<p>Previously, getting started on SageMaker Studio after discovering a model on Hugging Face required navigating multiple steps between opening Amazon SageMaker AI in the AWS Console, creating a domain, configuring IAM permissions, and sometimes requesting GPU quota. For developers who want to iterate quickly, this friction slows down the path from inspiration to experimentation. The integration creates a more direct path from discovery to enterprise deployment.</p>
<blockquote>
<p><em>“At Arcee, we build open models so developers and enterprises can actually own what they run: inspect the weights, post-train on their own data, and deploy on their own terms. This integration takes that promise the last mile. Going from an open model on Hugging Face straight into SageMaker Studio in a single click, then fine-tuning or deploying it inside your own AWS environment with nothing to wire up, is the kind of experience open models have been missing. Open weights you own, running in the cloud you control. That is exactly the combination our customers have been asking for.”</em></p>
</blockquote>
<p>— Mark McQuade, Founder and CEO, Arcee AI</p>
<p>With the launch of a one-click Studio landing experience, choosing <em>Customize on SageMaker AI</em> or <em>Deploy on SageMaker AI</em> on a supported Hugging Face model page takes you directly to the console. SageMaker AI then automatically provisions a new domain with pre-configured permissions in seconds and carries the model context through.</p>

	<a id="whats-new" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#whats-new" rel="nofollow">

	</a>
	<span>
		What’s new
	</span>
</h2>
<p>This launch introduces three capabilities that shorten the path from a Hugging Face model to a working SageMaker Studio workflow.</p>
<h3 class="relative group flex items-baseline">
	<a id="deep-links-from-hugging-face-into-sagemaker-studio" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#deep-links-from-hugging-face-into-sagemaker-studio" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Deep links from Hugging Face into SageMaker Studio
	</span>
</h3>
<p>When you browse models on Hugging Face, you’ll now see action buttons alongside supported models that map directly to SageMaker Studio workflows:</p>
<ul>
<li><strong>Customize on SageMaker AI</strong>&nbsp;opens the Model Customization page in Studio with the selected model pre-loaded, ready to fine-tune.</li>
<li><strong>Deploy on SageMaker AI</strong>&nbsp;opens the Deployment page in Studio with the model pre-configured for endpoint deployment.</li>
</ul>
<p>Each entry point preserves the context, meaning you don’t need to search for the model again once inside Studio.</p>
<h3 class="relative group flex items-baseline">
	<a id="pre-configured-permissions" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#pre-configured-permissions" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Pre-configured permissions
	</span>
</h3>
<p>New Studio environments created through this flow come with permissions already configured for the full range of SageMaker AI capabilities, including model customization, training jobs, notebook experimentation, and endpoint deployment. A new managed policy, <a href="https://aws.amazon.com/about-aws/whats-new/2026/01/quick-setup-model-customization-sagemaker-studio/" rel="nofollow">AmazonSageMakerModelCustomizationCoreAccess</a>, is created and attached for you. It provides permissions for serverless model customization jobs using supervised fine-tuning (SFT), direct preference optimization (DPO), reinforcement learning with verifiable rewards (RLVR), and reinforcement learning from AI feedback (RLAIF), with supported deployment to SageMaker AI or Amazon Bedrock endpoints. This alleviates the need to manually create and configure AWS Identity and Access Management (IAM) roles and policies before you can start experimenting. For existing Studio environments, actionable messages with direct links to documentation guide you through adding these permissions.</p>
<h3 class="relative group flex items-baseline">
	<a id="gpu-quota-visibility" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#gpu-quota-visibility" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		GPU quota visibility
	</span>
</h3>
<p>When selecting instance types for deployment or training, the Studio UI now surfaces quota availability directly in the instance selection list. You can immediately see which GPU instance types (G5, G6) are available under your account’s current limits. You don’t need to navigate separately to Service Quotas. If you still need to request a limit increase, you’re redirected directly to the Service Quotas page for the respective instance type.</p>
<h2 class="relative group flex items-baseline">
	<a id="walkthrough-deep-linking-from-hugging-face-to-sagemaker-studio" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#walkthrough-deep-linking-from-hugging-face-to-sagemaker-studio" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Walkthrough: Deep-linking from Hugging Face to SageMaker Studio
	</span>
</h2>
<p>Let’s walk through the experience of customizing or deploying a model starting from Hugging Face.</p>
<h3 class="relative group flex items-baseline">
	<a id="step-1-discover-and-select" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#step-1-discover-and-select" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Step 1: Discover and select
	</span>
</h3>
<p>On the Hugging Face model page, click on “Deploy” and select “Amazon SageMaker AI”. If the model is supported, you will see two buttons, “Deploy on SageMaker AI” and “Customize on SageMaker AI”. Then select “Customize on SageMaker AI” for a supported model. </p>
<p><a href="https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/06/ML-21254-1.png" rel="nofollow"><img src="https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/06/ML-21254-1.png" alt="Hugging Face model page showing the Customize on SageMaker AI button for a supported model"></a></p>
<h3 class="relative group flex items-baseline">
	<a id="step-2-sign-in" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#step-2-sign-in" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Step 2: Sign in
	</span>
</h3>
<p>You’re prompted to sign in to AWS using your existing credentials. If you already have an active console session, this step is skipped automatically. For more information, see <a href="https://docs.aws.amazon.com/signin/latest/userguide/how-to-sign-in.html" rel="nofollow">Sign in to the AWS Management Console</a>.</p>
<h3 class="relative group flex items-baseline">
	<a id="step-3-land-in-studio" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#step-3-land-in-studio" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Step 3: Land in Studio
	</span>
</h3>
<p>You arrive directly on the Model Customization page inside SageMaker Studio with your model pre-selected. Next, configure your fine-tuning parameters such as training data, hyperparameters, and instance type, then submit the customization job.</p>
<p><a href="https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/06/ML-21254-2.png" rel="nofollow"><img src="https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/06/ML-21254-2.png" alt="SageMaker Studio Model Customization page with the selected model pre-loaded and fine-tuning parameters ready to configure"></a></p>
<p>Alternatively, selecting <strong>Deploy on SageMaker AI</strong> opens the endpoint deployment page in Studio with the model pre-configured. Select your instance type (quota visibility included), review the settings, and deploy.</p>
<p><a href="https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/06/ML-21254-3.png" rel="nofollow"><img src="https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/06/ML-21254-3.png" alt="SageMaker Studio endpoint deployment page with the model pre-configured and instance type selection showing quota visibility"></a></p>
<h3 class="relative group flex items-baseline">
	<a id="step-4-test-your-endpoint" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#step-4-test-your-endpoint" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Step 4: Test your endpoint
	</span>
</h3>
<p>After you deploy your endpoint, test inference directly from Studio’s endpoint <a href="https://docs.aws.amazon.com/sagemaker/latest/dg/manage-endpoints-studio-test.html" rel="nofollow">testing interface</a>.</p>
<h2 class="relative group flex items-baseline">
	<a id="getting-started" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#getting-started" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Getting started
	</span>
</h2>
<p>You can try this experience today:</p>
<ol>
<li>Browse models on Hugging Face.</li>
<li>Look for the <strong>Customize on SageMaker AI</strong> or <strong>Deploy on SageMaker AI</strong> buttons on supported models.</li>
<li>Select and follow the streamlined sign-in flow.</li>
<li>Start building in a fully configured SageMaker Studio environment.</li>
</ol>
<h2 class="relative group flex items-baseline">
	<a id="conclusion" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#conclusion" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Conclusion
	</span>
</h2>
<p>The launch of a one-click Studio landing experience minimizes the friction between discovering a model and experimenting with it. By connecting Hugging Face directly to the SageMaker Studio workflows, developers can stay in their flow. There’s no context switching, no manual environment setup, and no permission troubleshooting.</p>
<p>To get started, visit the <a href="https://aws.amazon.com/sagemaker/ai/studio/" rel="nofollow">Amazon SageMaker Studio</a> page or explore models on Hugging Face and choose Deploy or Customize on SageMaker AI.</p>
