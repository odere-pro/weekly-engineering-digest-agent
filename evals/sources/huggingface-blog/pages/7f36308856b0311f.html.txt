<p><a href="https://huggingface.co/thinkingmachines/Inkling">Inkling</a> is a large (1T params!) open model to natively accept image, text, and audio inputs.</p>
<p>TLDR; Inkling by Thinking Machines is out on Hugging Face. Inkling is a huge multimodal LLM that understands all modalities (image, audio, text), has agentic capabilities, and supports 1M context. It comes in full BF16 and a well-calibrated NVFP4 variant, and includes speculative MTP layers for faster inference. There’s day-0 support in transformers, SGLang, vLLM, and llama.cpp. Thinking Machine Labs also released Inkling-Small with 276B total and 12B active parameters, as well as support for MXFP8 and NVFP4 weights, with the same architecture as Inkling.</p>
<h2 class="relative group flex items-baseline">
	<a id="what-makes-inkling-special" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#what-makes-inkling-special" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		What makes Inkling special?
	</span>
</h2>
<p>Inkling is the first large open model with <strong>~1T parameters</strong> and <strong>1M context window</strong> to natively receive <strong>image, text, and audio inputs</strong>, trained on <strong>45 trillion tokens of text, images, audio and video.</strong> It’s focused on reasoning across modalities such as audio, images, and text; and is intended for domain adaptation via fine-tuning. We’ve tinkered with this model to build some demos and explore the architecture, and we think it’s great for building a new wave of multimodal reasoning apps.</p>
<h2 class="relative group flex items-baseline">
	<a id="overall-capabilities-and-architecture" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#overall-capabilities-and-architecture" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Overall Capabilities and Architecture
	</span>
</h2>
<p>Inkling is a decoder-only multimodal Mixture-of-Experts model with 975B total and 41B active parameters. There are a lot of things going on, so let’s break each part down:</p>
<ul>
<li>Decoder-only: This means that the architecture supports causal autoregressive generation, like in most state-of-the-art LLMs.</li>
<li>Multimodal: The model can ingest text, audio, and images.</li>
<li>Mixture of Experts (MoE): The feed forward networks inside each layer are sparse, achieving faster inference because only 41B parameters are active at any given time. The model has 256 experts, as we’ll see later.</li>
</ul>
<p>Here’s a quick glance of the architecture.</p>
<p><strong>Relative attention:</strong> Instead of RoPE, which is the usual method to inject positional information in transformers models, Inkling uses relative attention to encode position information. Each attention layer learns position directly in the attention logits. Aside from key-query-values, there's a fourth projection producing a per-token, per-head relative feature R. This projection tensor is then tweaked with distance information (distance between the key and the query vector) and propagated into the attention module.</p>
<p><a href="https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/relative_attention.png" rel="nofollow"><img src="https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/relative_attention.png" alt="Inkling relative attention architecture"></a></p>
<p><strong>Hybrid attention:</strong> The decoder layers alternate between global attention (attending to the full context length at once) and sliding window attention (attending to a fixed context window in a sliding fashion). The architecture has a pattern of 5:1 sliding window to global attention layers. This hybrid attention scheme provides efficiency in computation. The final layer uses global attention to help build feature-rich representations.</p>
<p><strong>Short convolution:</strong> The model uses a distinctive short 1D convolution, or <code>SConv</code> over the hidden states. SConv reads the current token and the previous <code>W-1</code> hidden states, with <code>W</code> being the sliding window size. The intuition here is that SConv helps with local attention while freeing the attention and MoE modules from local representations.</p>
<p><a href="https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/sconv.png" rel="nofollow"><img src="https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/sconv.png" alt="Inkling short convolution architecture"></a></p>
<p><strong>MoE with shared experts sink:</strong> In Inkling, the router scores both routed experts and shared experts. Top-k selection is performed over 6 experts, plus 2 shared experts always active.</p>
<p><strong>Vision understanding:</strong> The model includes a simple hierarchical MLP patchifier consisting of several linear layers. Each layer merges pixels progressively, until the final layer produces one embedding per patch.</p>
<p><strong>Audio understanding:</strong> The architecture employs a discretized mel spectrogram, where each of the audio chunks (of 100 ms) are converted to the mel scale and then classified into the exact mel spectrogram bin.</p>
<p>The multimodal towers are relatively simple modules, unlike other models that employ separate encoders for each modality. Each image patch passes through the image embedding tower and the audio chunk is passed through the audio embedding tower to get both media embeddings. Image inputs also include an additional temporal dimension for video processing. We expect this capability to be useful for downstream fine-tuning, but we haven’t evaluated out-of-the-box video performance. The tower folds the patch grid, a small local block of neighboring tokens is stacked into the channel dimension and goes through hMLP. The audio waveform is converted to mel scale, which is then classified into a discrete mel bin. These mel bin values are embedded in the audio embedding tower and the embeddings are then summed to construct the final audio input.</p>

<h3 class="relative group flex items-baseline">
	<a id="sglang" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#sglang" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		SGLang
	</span>
</h3>
<p>SGLang is one of the fastest deployment frameworks for Inkling at the time of release, as it includes a custom model implementation. The launch command below shards the model across 8 GPUs and serves an OpenAI-compatible API on port 30000.</p>
<pre><code class="language-shell">pip install sglang

python3 -m sglang.launch_server \
 --model-path thinkingmachine/Inkling \
 --tp-size 8 \
 --served-model-name inkling \
 --host 0.0.0.0 \
 --port 30000
</code></pre>
<p>Match <code>--tp-size</code> to your GPU count. Add <code>--mem-fraction-static</code> (e.g. <code>0.85</code>) if you need to leave more headroom for the KV cache.</p>
<h3 class="relative group flex items-baseline">
	<a id="vllm" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#vllm" rel="nofollow">
		<span class="header-link"> </span>

	<span>
		vLLM

<p>vLLM is strong for production serving. A single <code>vllm serve</code> command downloads the weights from the Hub, shards the model across your GPUs with tensor parallelism, and starts an OpenAI-compatible server on port 8000. You can view the vLLM Recipe for the model <a href="https://recipes.vllm.ai/thinkingmachines/Inkling" rel="nofollow">here</a> to customize to your hardware.</p>
<pre><code class="language-shell"><span class="hljs-meta prompt_"># </span><span class="language-bash">Requires nightly or vllm&gt;=0.26 (once released)</span>
uv pip install -U vllm --pre \
  --extra-index-url https://wheels.vllm.ai/nightly/cu130 \
  --extra-index-url https://download.pytorch.org/whl/cu130 \
  --index-strategy unsafe-best-match

vllm serve thinkingmachines/Inkling-NVFP4 \
  --trust-remote-code \
  --tokenizer-mode inkling \
  --tensor-parallel-size 8 \
  --enable-auto-tool-choice \
  --tool-call-parser inkling \
  --reasoning-parser inkling \

<pre><code class="language-shell">curl http://localhost:8000/v1/chat/completions \

<h3 class="relative group flex items-baseline">
	<a id="multi-token-prediction-drafters" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#multi-token-prediction-drafters" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Multi Token Prediction Drafters
	</span>
</h3>
<p>MTP adds extra layers to the model that predict several tokens at once, not just the next one. During inference, the extra layers act as “drafters” for speculative decoding, speeding up generation without compromising performance. With MTP, you get the exact same generated outputs, multipliers in generation speed-up at small memory cost in VRAM (due to serving the drafter). Thinking Machines also provides an MTP drafter with this release.</p>
<pre><code class="language-python"><span class="hljs-keyword">import</span> torch

    dtype=torch.bfloat16,
    device_map=<span class="hljs-string">"auto"</span>,
)

<ul>
<li>Instead of directly answering the question on infographic, the model first turns text on image to text to ground itself.</li>
<li>Prompting matters a lot to save tokens in reasoning, for instance, asking vague questions like “which components interact here?” with an image of the back of a pill, the model first needs to see what we mean by interactions here.</li>
<li>Multi-choice question answers helped the model a lot in structuring its own reasoning, for open-ended questions the model struggled compared to MCQA, however, this is a common issue for many models. The usual chain of thought was OCR → characterize → evaluate each option → answer.</li>
<li>0.7 reasoning effort (medium) seems to provide a good trade-off.</li>
</ul>

Although this benchmark is initially made for speech-to-speech reasoning, we just want to see audio reasoning capabilities of this model. For GlobeAudio, the questions are relatively straightforward, so we ran with reasoning efforts of 0.1. We ran the first example of each language within GlobeAudio. All tests pass on all questions and efforts, except for second formal fallacy example on lowest effort, so we only provide the number of tokens spent in each question against reasoning effort. <p><strong>Some notes on the vibes:</strong></p>
<ul>
<li>Similar to vision, the model first transcribes the speech before answering the question.</li>
<li>It resists decoys: in Russian test, the model picked the right answer despite other answers appearing in the audio.</li>

<li>The effort helps reasoning and not hearing. Audio question answering was much cheaper than images.</li>
</ul>
<h3 class="relative group flex items-baseline">
	<a id="post-training" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#post-training" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Post-training
	</span>
</h3>
<p>If you would like to use Inkling for post-training, Thinking Machines have built <code>tinker</code>, a managed tool for post-training open weight models. Their cookbook includes examples for fine-tuning, distillation, and reinforcement learning.</p>
<p>We post trained Inkling with tinker and OpenEnv, an agentic RL environment tool. We used the ECHO algorithm that trains a model to predict the environment without a verifier, applying next-token cross-entropy loss to tokens produced by the environment, alongside the usual policy learning on agent actions. This teaches the policy an implicit world model without requiring a separate model, teacher, or additional rollouts. Check out the <a href="https://github.com/huggingface/OpenEnv/blob/main/examples/echo_world_model/backends/tinker_echo_demo.py" rel="nofollow">example</a>.</p>
<p><a href="https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/trackio.png" rel="nofollow"><img src="https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/trackio.png" alt="Inkling post-training metrics"></a></p>
<details>
<summary>RL Example with Tinker and OpenEnv</summary>

<pre><code>git clone https://github.com/huggingface/OpenEnv.git
cd OpenEnv

# Add TINKER_API_KEY=... to .env, then run:
uv run --env-file .env \
  examples/echo_world_model/backends/tinker_echo_demo.py
</code></pre>
</details>

<p>If you’re working with Transformers Reinforcement Learning we suggest using Inkling as a teacher model in a knowledge distillation setup. For example, take advantage of Inkling’s document understanding abilities to improve the performance of a smaller (on-device) model. In <a href="https://github.com/huggingface/trl/blob/main/examples/gold_chatbot_arena/gold_chatbot_arena.py" rel="nofollow">this example</a>, we use the transformer reinforcement learning library and the GOLD algorithm to distill knowledge. GOLD is handy here because it matches token logits between different tokenizers, so you can distill to any model on the hub.</p>
