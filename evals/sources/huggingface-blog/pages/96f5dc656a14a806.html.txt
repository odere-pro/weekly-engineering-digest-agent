<p><!--[--><!--[0--><div class="absolute -left-12 bottom-0 top-0 z-30 not-prose hidden lg:block"><div class="sticky top-4 flex"><div class="h-7 pt-[0.175rem]"><span class="peer" tabindex="0"><button class="select-none text-gray-400 hover:cursor-pointer hover:text-gray-800 dark:text-gray-500 dark:hover:text-gray-400"> <!----></button></span> <div class="invisible w-0 -translate-x-8 -translate-y-6 overflow-hidden rounded-xl border bg-white transition-transform hover:visible hover:w-52 hover:translate-x-0 peer-focus-within:visible peer-focus-within:w-52 peer-focus-within:translate-x-0"> </div></div></div></div><!--]--><!--]-->Large diffusion transformers can create stunning images (or even videos, audio snippets, and now text), but loading a modern text-to-image model in BF16 precision often requires 20-30 GB of VRAM, which puts these models out of reach of most consumer GPUs. Quantization is a powerful solution to this problem, and Diffusers already integrates several quantization backends such as bitsandbytes, GGUF, torchao, and Quanto, which we covered in <a href="https://huggingface.co/blog/diffusers-quantization">Exploring Quantization Backends in Diffusers</a>.</p>
<p>Most of these backends are <em>weight-only</em>. This means that they store the weights in low precision and dequantize them back to high precision at compute time. This reduces memory usage significantly, but it usually does not make inference faster, and can even add a small latency overhead.</p>
<p><a href="https://arxiv.org/abs/2411.05007" rel="nofollow">SVDQuant</a>, the quantization method behind the popular <a href="https://github.com/nunchaku-tech/nunchaku" rel="nofollow">Nunchaku</a> inference engine, takes a different approach. It runs the main transformer layers with 4-bit weights and activations (W4A4), reducing memory while also speeding up the denoising loop. The details are covered below, but until now, using these checkpoints required a separate inference library.</p>
<p>With current Diffusers, loading a Nunchaku checkpoint is as simple as calling <code>from_pretrained()</code>, with no local CUDA compilation required thanks to the <a href="https://github.com/huggingface/kernels" rel="nofollow"><code>kernels</code></a> package. In addition, the companion <a href="https://github.com/rootonchair/diffuse-compressor" rel="nofollow">diffuse-compressor</a> toolkit lets you quantize new architectures yourself and publish them as regular Diffusers repositories.</p>

</figure>

<h2 class="relative group flex items-baseline">
	<a id="getting-started-with-nunchaku-lite" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#getting-started-with-nunchaku-lite" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Getting started with Nunchaku Lite
	</span>
</h2>
<p>First, install the requirements. You need a recent version of Diffusers and the Hugging Face <code>kernels</code> package:</p>
<pre><code class="language-bash">pip install -U diffusers transformers accelerate kernels bitsandbytes
</code></pre>
<p>Then load a pre-quantized pipeline like any other Diffusers model:</p>
<pre><code class="language-python"><span class="hljs-keyword">import</span> torch
<span class="hljs-keyword">from</span> diffusers <span class="hljs-keyword">import</span> ErnieImagePipeline

pipe = ErnieImagePipeline.from_pretrained(
    <span class="hljs-string">"lite-infer/ERNIE-Image-Turbo-nunchaku-lite-nvfp4_r32-bnb4-text-encoder"</span>,
    torch_dtype=torch.bfloat16,
).to(<span class="hljs-string">"cuda"</span>)

image = pipe(
    prompt=<span class="hljs-string">"A cinematic portrait of a red fox in a misty forest at sunrise, "</span>
           <span class="hljs-string">"detailed fur, volumetric light"</span>,
    height=<span class="hljs-number">1024</span>,
    width=<span class="hljs-number">1024</span>,
    num_inference_steps=<span class="hljs-number">8</span>,
    guidance_scale=<span class="hljs-number">1.0</span>,
    generator=torch.Generator(<span class="hljs-string">"cuda"</span>).manual_seed(<span class="hljs-number">42</span>),
).images[<span class="hljs-number">0</span>]
image.save(<span class="hljs-string">"output.png"</span>)
</code></pre>
<figure class="image text-center">
  <img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/nunchaku-diffusers/fox_bf16_vs_nunchaku_no_metrics.png" alt="BF16 and Nunchaku Lite outputs for a red fox prompt">
</figure>

<p>No custom pipeline class or separate inference engine is needed, and there is nothing to compile locally. The NVFP4 kernels are downloaded from the Hub through the <a href="https://huggingface.co/kernels/rootonchair/nunchaku-lite-kernels">Nunchaku Lite kernels page</a> the first time they are used. This checkpoint pairs a Nunchaku NVFP4 transformer with a bitsandbytes NF4 text encoder, and generates a 1024x1024 image in about 1.7 seconds on an RTX 5090 with a peak memory usage of about 12 GB, compared with about 24 GB for the BF16 pipeline. You can find more details about the Nunchaku Lite checkpoint format in the <a href="https://huggingface.co/docs/diffusers/main/en/quantization/nunchaku">official Diffusers documentation</a>.</p>
<blockquote class="note">
<p>NVFP4 checkpoints require an NVIDIA Blackwell GPU (RTX 50 series, RTX PRO 6000, B200). For earlier generations, use the INT4 variants. See the <a href="#hardware-support" rel="nofollow">hardware support</a> table below for details.</p>
</blockquote>
<h2 class="relative group flex items-baseline">
	<a id="background-svdquant-and-nunchaku" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#background-svdquant-and-nunchaku" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Background: SVDQuant and Nunchaku
	</span>
</h2>
<p><strong>SVDQuant</strong> is the quantization method behind <strong>Nunchaku</strong>, its reference CUDA inference engine. Standard 4-bit quantization is difficult for diffusion transformers because both weights and activations contain large outliers. SVDQuant handles this by moving activation outliers into the weights, representing the hardest part of each weight matrix with a small 16-bit low-rank branch, and quantizing the remaining residual to 4 bits. Nunchaku makes this fast with fused kernels for the 4-bit path and the low-rank branch.</p>
<figure class="image text-center">
  <img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/nunchaku-diffusers/svdquant_kernel_fusion.png" alt="Nunchaku kernel fusion: the low-rank down projection is fused with input quantization, and the low-rank up projection is fused with the 4-bit matmul">
  <figcaption>Nunchaku fuses the low-rank down projection with the quantization kernel and the low-rank up projection with the 4-bit compute kernel, eliminating the memory access overhead of the 16-bit branch. Figure from the <a href="https://arxiv.org/abs/2411.05007" rel="nofollow">SVDQuant paper</a>.</figcaption>
</figure>

<h2 class="relative group flex items-baseline">
	<a id="introducing-nunchaku-lite" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#introducing-nunchaku-lite" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Introducing Nunchaku Lite
	</span>
</h2>
<p>The original <a href="https://github.com/nunchaku-ai/nunchaku" rel="nofollow">Nunchaku engine</a> gets much of its speed from <a href="#quantizing-models-with-structural-rewrites" rel="nofollow">model-specific fused execution paths</a>, such as fused QKV projections and fused GELU/MLP kernels. Those optimizations are tied to each architecture's module layout and checkpoint format, so supporting a new model family usually requires model-specific integration work.</p>
<p><strong>Nunchaku Lite</strong> is the new integration path in Diffusers. With it, Diffusers can load Nunchaku-style checkpoints without a custom pipeline or a separate inference engine. Under the hood, Nunchaku Lite patches the relevant <code>nn.Linear</code> modules of a stock Diffusers model with runtime SVDQ/AWQ linear layers before the checkpoint is loaded. The CUDA kernels come from the Hub through the <code>kernels</code> package. Two kernel families are used:</p>
<ul>
<li><strong><code>svdq_w4a4</code></strong>: 4-bit weights and activations with the SVDQuant low-rank correction. This layer is used for the transformer's attention and MLP projections, where nearly all of the compute is spent, and is available in INT4 and NVFP4 variants.</li>
<li><strong><code>awq_w4a16</code></strong>: 4-bit weights with 16-bit activations, used for adaptive normalization and modulation projections such as FLUX <code>adanorm_single</code> / <code>adanorm_zero</code> or Qwen-Image modulation layers. These layers are memory-bound and precision-sensitive, making AWQ a good fit to preserve precision while still saving memory and space.</li>
</ul>
<p>The trade-off is that, without architecture-specific fused kernels and modules, Nunchaku Lite cannot match the speedup of the original Nunchaku engine. However, the bare-bones implementation still delivers around <strong>30% speedup</strong> while retaining the same level of <strong>VRAM reduction</strong>.</p>
<h2 class="relative group flex items-baseline">
	<a id="native-loading-in-diffusers" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#native-loading-in-diffusers" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Native loading in Diffusers
	</span>
</h2>
<p>If you have used bitsandbytes or torchao in Diffusers, the mechanics will feel familiar. A Nunchaku Lite model repository is an ordinary Diffusers repository. The only special part is a <code>quantization_config</code> block inside the transformer's <code>config.json</code>:</p>
<pre><code class="language-json"><span class="hljs-attr">"quantization_config"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
    <span class="hljs-attr">"quant_method"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"nunchaku_lite"</span><span class="hljs-punctuation">,</span>
    <span class="hljs-attr">"compute_dtype"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"bfloat16"</span><span class="hljs-punctuation">,</span>
    <span class="hljs-attr">"svdq_w4a4"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
        <span class="hljs-attr">"precision"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"nvfp4"</span><span class="hljs-punctuation">,</span>
        <span class="hljs-attr">"group_size"</span><span class="hljs-punctuation">:</span> <span class="hljs-number">16</span><span class="hljs-punctuation">,</span>
        <span class="hljs-attr">"rank"</span><span class="hljs-punctuation">:</span> <span class="hljs-number">32</span><span class="hljs-punctuation">,</span>
        <span class="hljs-attr">"targets"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">[</span>
            <span class="hljs-string">"layers.0.self_attention.to_q"</span><span class="hljs-punctuation">,</span>
            <span class="hljs-string">"layers.0.self_attention.to_k"</span><span class="hljs-punctuation">,</span>
            <span class="hljs-string">"..."</span>
        <span class="hljs-punctuation">]</span>
    <span class="hljs-punctuation">}</span><span class="hljs-punctuation">,</span>
    <span class="hljs-attr">"awq_w4a16"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">{</span>
        <span class="hljs-attr">"precision"</span><span class="hljs-punctuation">:</span> <span class="hljs-string">"int4"</span><span class="hljs-punctuation">,</span>
        <span class="hljs-attr">"group_size"</span><span class="hljs-punctuation">:</span> <span class="hljs-number">64</span><span class="hljs-punctuation">,</span>
        <span class="hljs-attr">"targets"</span><span class="hljs-punctuation">:</span> <span class="hljs-punctuation">[</span>
            <span class="hljs-string">"adaLN_modulation.1"</span><span class="hljs-punctuation">,</span>
            <span class="hljs-string">"..."</span>
        <span class="hljs-punctuation">]</span>
    <span class="hljs-punctuation">}</span>
<span class="hljs-punctuation">}</span>
</code></pre>
<p>This config tells Diffusers which modules were quantized, which scheme they use, and which Nunchaku Lite runtime layer to instantiate (<code>SVDQW4A4Linear</code> or <code>AWQW4A16Linear</code>).</p>
<p>Because the quantized model keeps the exact module structure of the dense one, everything downstream (schedulers, LoRA loading hooks, offloading, <code>torch.compile</code>) sees a normal Diffusers model.</p>

<h2 class="relative group flex items-baseline">
	<a id="getting-more-speed-and-lower-memory" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#getting-more-speed-and-lower-memory" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Getting more speed and lower memory
	</span>
</h2>
<p>Nunchaku Lite can be combined with other Diffusers memory and speed optimizations.</p>
<p><strong><code>torch.compile</code>.</strong> Compiling the transformer improves the end-to-end speedup from 1.35x to 1.8x:</p>
<pre><code class="language-python">pipe.transformer.<span class="hljs-built_in">compile</span>(fullgraph=<span class="hljs-literal">True</span>)

<span class="hljs-comment"># or compile_repeated_blocks() for faster compilation</span>

pipe.transformer.compile_repeated_blocks(fullgraph=<span class="hljs-literal">True</span>)
</code></pre>
<p><strong>Quantized text encoders.</strong> The transformer is not the only component with a large memory footprint. Text encoders such as T5 or Qwen3 can occupy several gigabytes on their own. Further quantizing the text encoder with bitsandbytes NF4 reduces peak VRAM by about 22% in our benchmark.</p>
<p><strong>Offloading.</strong> Diffusers offloading helpers such as <code>enable_model_cpu_offload()</code> and <code>enable_sequential_cpu_offload()</code> work as usual if you need to fit the pipeline onto a smaller GPU.</p>

<h2 class="relative group flex items-baseline">
	<a id="quantizing-your-own-model" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#quantizing-your-own-model" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Quantizing your own model
	</span>
</h2>
<p>Nunchaku Lite support in Diffusers is architecture-agnostic, and the <a href="https://github.com/rootonchair/diffuse-compressor" rel="nofollow">diffuse-compressor</a> toolkit provides an end-to-end SVDQuant workflow for Diffusers models: calibrate, quantize, package, and publish.</p>
<p>Below, we walk through quantizing FLUX.2 Klein 4B as an example. It covers the main steps: inspect the model, calibrate and quantize the transformer, package the result as a Diffusers pipeline, then verify and push it to the Hub. The <a href="https://github.com/rootonchair/diffuse-compressor/blob/main/docs/quantize_new_hf_model.md" rel="nofollow">full tutorial</a> covers every flag in detail.</p>
<h3 class="relative group flex items-baseline">
	<a id="1-inspect-what-will-be-quantized" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#1-inspect-what-will-be-quantized" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		1. Inspect what will be quantized
	</span>
</h3>
<p>The generic scanner walks the model and decides what to target: compatible linears inside the repeated transformer-block stack become SVDQ W4A4 targets, recognized modulation linears become AWQ W4A16 targets, and everything else stays dense.</p>
<pre><code class="language-bash">python examples/text_to_image/quantize_hf.py black-forest-labs/FLUX.2-klein-4B \
  --precision int4 --rank 32 --inspect-config
</code></pre>
<p>Always read this report before quantizing. For FLUX.2 Klein 4B, the expected result is 100 SVDQ targets, 3 AWQ targets, and 6 dense outer linears, with no missing patterns or duplicate names.</p>
<h3 class="relative group flex items-baseline">
	<a id="2-run-quantization" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#2-run-quantization" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		2. Run quantization
	</span>
</h3>
<p>The following command runs SVDQuant on the transformer and writes the quantized checkpoint to <code>outputs/checkpoints/svdq-int4_r32-flux-2-klein-4b.safetensors</code>:</p>
<pre><code class="language-bash">python examples/text_to_image/quantize_hf.py black-forest-labs/FLUX.2-klein-4B \
  --precision int4 \
  --output outputs/checkpoints/svdq-int4_r32-flux-2-klein-4b.safetensors
</code></pre>
<p>Replace <code>--precision int4</code> with <code>nvfp4</code> to build Blackwell-native weights.</p>
<h3 class="relative group flex items-baseline">
	<a id="3-package-a-diffusers-pipeline" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#3-package-a-diffusers-pipeline" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		3. Package a Diffusers pipeline
	</span>
</h3>
<p>The converter combines the quantized transformer with the base pipeline's other components, writes the compact <code>nunchaku_lite</code> configuration into <code>transformer/config.json</code>, and can optionally convert text encoders to NF4:</p>
<pre><code class="language-bash">python examples/convert_nunchaku_lite_diffusers.py \
  --checkpoint outputs/checkpoints/svdq-int4_r32-flux-2-klein-4b.safetensors \
  --model-id black-forest-labs/FLUX.2-klein-4B \
  --bnb4-text-encoder text_encoder \
  --compute-dtype bfloat16 \
  --output-dir outputs/diffusers/FLUX.2-klein-4B-nunchaku-lite-int4-bnb4-text-encoder
</code></pre>
<h3 class="relative group flex items-baseline">
	<a id="4-load-verify-and-push-to-the-hub" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#4-load-verify-and-push-to-the-hub" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		4. Load, verify, and push to the Hub
	</span>
</h3>
<pre><code class="language-python"><span class="hljs-keyword">import</span> torch
<span class="hljs-keyword">from</span> diffusers <span class="hljs-keyword">import</span> DiffusionPipeline

pipe = DiffusionPipeline.from_pretrained(
    <span class="hljs-string">"outputs/diffusers/FLUX.2-klein-4B-nunchaku-lite-int4-bnb4-text-encoder"</span>,
    device_map=<span class="hljs-string">"cuda"</span>,
)
image = pipe(
    <span class="hljs-string">"A glass robot in a greenhouse, cinematic lighting"</span>,
    num_inference_steps=<span class="hljs-number">4</span>, guidance_scale=<span class="hljs-number">1.0</span>,
    generator=torch.Generator(<span class="hljs-string">"cuda"</span>).manual_seed(<span class="hljs-number">12345</span>),
).images[<span class="hljs-number">0</span>]
</code></pre>
<p>Once the outputs look good, run <code>pipe.push_to_hub("your-name/your-model-nunchaku-lite-int4")</code>. Other users can then load it with the same <code>from_pretrained()</code> pattern shown above.</p>
<h3 class="relative group flex items-baseline">
	<a id="quantizing-models-with-structural-rewrites" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#quantizing-models-with-structural-rewrites" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Quantizing models with structural rewrites
	</span>
</h3>
<p>Note that the generic path assumes the architecture can be quantized without structural rewrites. For additional speedup, the original Nunchaku engine rewrites groups of Diffusers layers as fused modules. The generic path cannot infer these changes on its own, such as combining separate Q, K, and V projections into one module or splitting a fused projection across several modules.</p>
<p>FLUX.1-dev's QKV projection is a concrete example. <a href="https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/transformers/transformer_flux.py#L313-L329" rel="nofollow">Diffusers defines three separate modules</a>:</p>
<pre><code class="language-python">self.to_q = torch.nn.Linear(query_dim, self.inner_dim, bias=bias)
self.to_k = torch.nn.Linear(query_dim, self.inner_dim, bias=bias)
self.to_v = torch.nn.Linear(query_dim, self.inner_dim, bias=bias)
</code></pre>
<p>The <a href="https://github.com/nunchaku-ai/nunchaku/blob/main/nunchaku/models/transformers/transformer_flux_v2.py#L63-L79" rel="nofollow">Nunchaku FLUX module combines those layers</a> into one quantized <code>to_qkv</code> module:</p>
<pre><code class="language-python">to_qkv = fuse_linears([other.to_q, other.to_k, other.to_v])
self.to_qkv = SVDQW4A4Linear.from_linear(to_qkv, **kwargs)
</code></pre>
<p>This grouped module is required because Nunchaku's fused operator consumes the QKV projection, Q/K normalization, and rotary embeddings together. By comparison, the <a href="https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/transformers/transformer_flux.py#L45-L116" rel="nofollow">default Diffusers path</a> executes them separately:</p>
<pre><code class="language-python">query = attn.to_q(hidden_states)
key = attn.to_k(hidden_states)
value = attn.to_v(hidden_states)

query = query.unflatten(-<span class="hljs-number">1</span>, (attn.heads, -<span class="hljs-number">1</span>))
key = key.unflatten(-<span class="hljs-number">1</span>, (attn.heads, -<span class="hljs-number">1</span>))
value = value.unflatten(-<span class="hljs-number">1</span>, (attn.heads, -<span class="hljs-number">1</span>))

query = attn.norm_q(query)
key = attn.norm_k(key)

<span class="hljs-keyword">if</span> image_rotary_emb <span class="hljs-keyword">is</span> <span class="hljs-keyword">not</span> <span class="hljs-literal">None</span>:
    query = apply_rotary_emb(query, image_rotary_emb, sequence_dim=<span class="hljs-number">1</span>)
    key = apply_rotary_emb(key, image_rotary_emb, sequence_dim=<span class="hljs-number">1</span>)
</code></pre>
<p>The <a href="https://github.com/nunchaku-ai/nunchaku/blob/main/nunchaku/models/attention_processors/flux.py#L69-L93" rel="nofollow">Nunchaku path</a> supplies the grouped projection, normalization modules, and rotary embeddings to one fused operator:</p>
<pre><code class="language-python">qkv = fused_qkv_norm_rottary(
    hidden_states, attn.to_qkv, attn.norm_q, attn.norm_k, image_rotary_emb
)
</code></pre>
<p>This is the structural rewrite that the generic path cannot infer. Diffusers has three destination modules with <code>to_q</code>, <code>to_k</code>, and <code>to_v</code> parameter prefixes, while Nunchaku has one grouped module under <code>to_qkv</code>. A model-specific target config or adapter must state that the Q, K, and V parameters should be concatenated along the output dimension, in that order, and loaded into <code>to_qkv</code>.</p>
<p>Structural rewrites like these are described by a model-specific target config during quantization and handled by a small runtime adapter when the checkpoint is loaded.
The <a href="https://github.com/rootonchair/diffuse-compressor/blob/main/examples/text_to_image/quantize_flux2_klein_4b.py" rel="nofollow">FLUX.2 Klein 4B quantization script</a> provides a concrete target-config example for producing a structurally rewritten checkpoint, while <a href="https://github.com/rootonchair/nunchaku-lite" rel="nofollow">rootonchair/nunchaku-lite</a> provides the runtime adapters needed to load grouped QKV tensors, split fused projections, and other fused operations.
For the complete workflow, you can check the <a href="https://github.com/rootonchair/diffuse-compressor/blob/main/docs/adding_new_model.md" rel="nofollow">Adding A New Model</a> guide.</p>

<h2 class="relative group flex items-baseline">
	<a id="conclusion" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#conclusion" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Conclusion
	</span>
</h2>
<p>Nunchaku's SVDQuant kernels are one of the most effective ways to run diffusion transformers efficiently on consumer hardware, and they are now natively supported in Diffusers. Pre-quantized checkpoints load with <code>from_pretrained()</code>, and the diffuse-compressor toolkit makes it possible to quantize new architectures without waiting for engine support. By quantizing both weights and activations, the W4A4 path lowers memory use while improving denoising latency, keeping image quality close to the BF16 original.</p>
<p>If you quantize and publish a new model, we would love to hear about it. Share it on the Hub and let us know! If you have any questions about this feature, feel free to join our <a href="https://discord.gg/G7tWnz98XR" rel="nofollow">Discord</a>.</p>
