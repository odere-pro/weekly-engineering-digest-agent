	<span>
		TL;DR
	</span>
</h2>
<ul>
<li>One model for text-to-image, multi-reference image-to-image, and bounding-box layout control.</li>
<li>The distilled checkpoint makes a 1024 × 1024 image in about <strong>2 seconds</strong> on an H100.</li>
<li>NVFP4 and FP8 weights load with <code>from_single_file</code>, for smaller GPUs.</li>
<li>LoRA training scripts for both text-to-image and image editing.</li>
<li>Ships as a <a href="#modular-diffusers" rel="nofollow">Modular Diffusers</a> pipeline, so you can pop blocks out or add your own.</li>
</ul>

<h2 class="relative group flex items-baseline">
	<a id="getting-started" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#getting-started" rel="nofollow">

	</a>
	<span>
		Getting started
	</span>
</h2>
<p>Install the latest <code>diffusers</code> and <code>transformers</code> (for the Qwen3-VL text encoder):</p>
<pre><code class="language-bash">pip install -U diffusers transformers
</code></pre>
<p>Load the distilled checkpoint and generate an image:</p>
<pre><code class="language-python"><span class="hljs-keyword">import</span> torch
<span class="hljs-keyword">from</span> diffusers <span class="hljs-keyword">import</span> ModularPipeline

pipe = ModularPipeline.from_pretrained(<span class="hljs-string">"black-forest-labs/flux-3-image-klein"</span>)
pipe.load_components(dtype=torch.bfloat16)
pipe.to(<span class="hljs-string">"cuda"</span>)

pipe(prompt=<span class="hljs-string">"a red fox"</span>, output=<span class="hljs-string">"images"</span>)[<span class="hljs-number">0</span>].save(<span class="hljs-string">"fox.png"</span>)
</code></pre>

	<span>
		What FLUX.3 can do
	</span>
</h2>
<h3 class="relative group flex items-baseline">
	<a id="text-to-image" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#text-to-image" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Text-to-image
	</span>
</h3>
<p>FLUX.3 responds best to a full scene description with the subject, the setting, the light, the composition, and the style. The <a href="https://docs.bfl.ai/guides/prompting_summary" rel="nofollow">official prompting guide</a> from Black Forest Labs has more tips. The distilled checkpoint generates a <code>1024 × 1024</code> image in <code>16</code> steps by default. Pass <code>height</code>, <code>width</code>, or <code>num_inference_steps</code> to change them.</p>
<pre><code class="language-python">prompt = (
    <span class="hljs-string">"A wide-angle wildlife photograph of a red fox standing alert in a snow-covered forest clearing at golden hour. "</span>
    <span class="hljs-string">"The fox is centered in the frame, its thick orange winter coat contrasting with the fresh white snow, breath "</span>
    <span class="hljs-string">"visible in the cold air. Snow-laden pine trees fill the softly blurred background, and low warm sunlight rakes "</span>
    <span class="hljs-string">"across the scene from the left, casting long blue shadows."</span>
)

fox = pipe(
    prompt=prompt,
    generator=torch.Generator().manual_seed(<span class="hljs-number">0</span>),
    output=<span class="hljs-string">"images"</span>
)[<span class="hljs-number">0</span>]
fox.save(<span class="hljs-string">"fox.png"</span>)
</code></pre>

<h3 class="relative group flex items-baseline">
	<a id="single-file-format-checkpoints" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#single-file-format-checkpoints" rel="nofollow">

	<span>
		Single-file format checkpoints
	</span>
</h3>
<p>Black Forest Labs also ships the transformer as a single file, in <code>bf16</code> and in two quantized formats: <code>fp8r</code> (rowwise FP8) and <code>nvfp4</code>. Load any of them with <code>from_single_file</code>, then load the other components by name so the bf16 transformer isn't downloaded too.</p>
<pre><code class="language-python"><span class="hljs-keyword">from</span> diffusers <span class="hljs-keyword">import</span> BFLQuantizationConfig, Flux3Transformer2DModel, ModularPipeline

model_id = <span class="hljs-string">"black-forest-labs/flux-3-image-klein-base"</span>
variant = <span class="hljs-string">"fp8r"</span>  <span class="hljs-comment"># or "nvfp4"</span>

transformer = Flux3Transformer2DModel.from_single_file(
    <span class="hljs-string">f"https://huggingface.co/<span class="hljs-subst">{model_id}</span>/blob/main/variants/<span class="hljs-subst">{variant}</span>/model.safetensors"</span>,
    config=model_id,
    subfolder=<span class="hljs-string">"transformer"</span>,
    quantization_config=BFLQuantizationConfig(compute_dtype=torch.bfloat16),
    dtype=torch.bfloat16,
)

pipe = ModularPipeline.from_pretrained(model_id)
pipe.load_components(dtype=torch.bfloat16)
pipe.update_components(transformer=transformer)
pipe.to(<span class="hljs-string">"cuda"</span>)
</code></pre>

<h2 class="relative group flex items-baseline">
	<a id="lora-finetuning" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#lora-finetuning" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		LoRA finetuning
	</span>
</h2>
<p>FLUX.3 works for both text-to-image and image-to-image, which makes it a great base for custom LoRAs. <code>diffusers</code> ships DreamBooth LoRA training scripts for both tasks (you can also train with <a href="https://github.com/ostris/ai-toolkit" rel="nofollow">Ostris' AI Toolkit</a>).</p>
<p>Here is a text-to-image example that learns a tarot-card style from the <a href="https://huggingface.co/datasets/multimodalart/1920-raider-waite-tarot-public-domain"><code>multimodalart/1920-raider-waite-tarot-public-domain</code></a> dataset, triggered with <code>trtcrd</code>:</p>
<pre><code class="language-bash">accelerate launch train_dreambooth_lora_flux3_klein.py \
  --pretrained_model_name_or_path=<span class="hljs-string">"black-forest-labs/flux-3-image-klein-base"</span> \
  --dataset_name=<span class="hljs-string">"multimodalart/1920-raider-waite-tarot-public-domain"</span> \
  --caption_column=<span class="hljs-string">"caption"</span> \
  --instance_prompt=<span class="hljs-string">"trtcrd"</span> \
  --output_dir=<span class="hljs-string">"trained-flux3-tarot-lora"</span> \
  --mixed_precision=<span class="hljs-string">"bf16"</span> \
  --resolution=1024 \
  --use_aspect_ratio_buckets \
  --train_batch_size=1 \
  --rank=16 \
  --lora_alpha=16 \
  --learning_rate=1e-4 \
  --lr_scheduler=<span class="hljs-string">"constant"</span> \
  --max_train_steps=1500 \
  --validation_prompt=<span class="hljs-string">"a trtcrd of a cat, tarot style"</span> \
  --validation_epochs=25 \
  --seed=0 \
  --push_to_hub
</code></pre>
<blockquote class="note">
<p>To reduce memory usage, add a few optimization flags:</p>
<pre><code class="language-bash">  --gradient_checkpointing \
  --cache_latents \
  --use_8bit_adam
</code></pre>
<p><code>--gradient_checkpointing</code> recomputes activations in the backward pass (lower VRAM, slightly slower), <code>--cache_latents</code> pre-encodes the images and frees the VAE, and <code>--use_8bit_adam</code> keeps the optimizer states in 8-bit.</p>
</blockquote>
<p>A couple of knobs are worth experimenting with. The grid below trains the same tarot style with different LoRA ranks and optimizers; the adapters are on the Hub at <a href="https://huggingface.co/diffusers-modular/flux3-tarot-lora"><code>diffusers-modular/flux3-tarot-lora</code></a>. More training features and configurations are documented in the <a href="https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/README_flux3_klein.md" rel="nofollow">DreamBooth FLUX.3 README</a>.</p>
<p><a href="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/flux3/tarot-lora-sweep.png" rel="nofollow"><img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/flux3/tarot-lora-sweep.png" alt="FLUX.3 tarot-style LoRA across ranks and optimizers: the base model with no LoRA, then rank 16, rank 8 and rank 32 (AdamW, lr 1e-4) and a Prodigy run, on two held-out prompts"></a></p>
<p>For instruction-based editing, the image-to-image script (<code>train_dreambooth_lora_flux3_klein_img2img.py</code>) trains on (reference image, target image, instruction) triplets, where the reference is addressed in the prompt as <code>&lt;ref_image_0&gt;</code>.</p>
<p>See the <a href="https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/README_flux3_klein.md" rel="nofollow">DreamBooth FLUX.3 README</a> for all options and the full image-to-image example.</p>

<h2 class="relative group flex items-baseline">
	<a id="the-architecture" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#the-architecture" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		The architecture
	</span>
</h2>
<p>Let's open the model up, one piece at a time. The model takes three kinds of tokens:</p>
<ol>
<li><strong>text</strong></li>
<li>the <strong>noisy image</strong> being generated</li>
<li>and optional <strong>reference images</strong></li>
</ol>
<h3 class="relative group flex items-baseline">
	<a id="from-pixels-to-tokens" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#from-pixels-to-tokens" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		From pixels to tokens
	</span>
</h3>
<p>FLUX.3 is a latent-space flow model for image generation. This means that the denoiser takes latents as inputs and produces latents as outputs. We use a VAE to decode the latents back to pixels. FLUX.3 uses the same VAE architecture as Flux.2. </p>
<p>The FLUX.2 VAE compresses an image 8× in each direction into 32 channels, and then every 2 × 2 patch of that latent is packed into a single token with 128 channels.</p>
<p>So <strong>one token covers a 16 × 16 pixel patch</strong>, and a 1024 × 1024 image becomes a 64 × 64 grid of 4,096 tokens. The noisy image starts as random noise of exactly that shape. A reference image goes through the same VAE encoder and packing, and keeps its own size.</p>
<h3 class="relative group flex items-baseline">
	<a id="from-prompt-to-tokens" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#from-prompt-to-tokens" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		From prompt to tokens
	</span>
</h3>
<p>The text encoder is Qwen3-VL, a vision-language model. FLUX.3 doesn't just take its last layer. It reads the hidden states of <strong>eight</strong> of its 36 layers (layers 4, 8, …, 32) and stacks them, so each text token becomes a 8 × 2560 = 20,480-dimensional vector before a linear layer projects it to the transformer's width of 3072.</p>
<p>This gives the transformer features from several depths of the language model, not just its final layer. The prompt is padded to a multiple of 80 tokens, and the transformer attends to the padding too, which is why the pipeline takes one prompt per call.</p>
<h3 class="relative group flex items-baseline">
	<a id="two-stages" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#two-stages" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Two stages
	</span>
</h3>
<p>The transformer processes the tokens in two stages:</p>
<ol>
<li><strong>Stage 1: per-mode blocks.</strong> Each stream goes through 5 blocks with its own weights. Text has its own blocks, the noisy image has its own, and the reference images have their own.</li>
<li><strong>Stage 2: joint blocks.</strong> The streams are concatenated into one sequence, <code>[text | image | reference]</code>, which goes through 28 blocks that share one set of weights.</li>
</ol>
<p>The two stages differ in <em>who can attend to whom</em>.</p>
<p>In stage 1, each stream only attends to itself, so each kind of token gets refined on its own terms first. In stage 2, everything attends to everything, where the image learns from the text and from the references. For comparison, FLUX.2's double-stream blocks also give text and image separate weights, but let them attend to each other from the start. FLUX.3 keeps the streams fully apart first, then merges them.</p>
<p>At the end, the text and reference tokens are simply dropped. Only the image tokens go through the output layers, which predict how to move them one step toward a clean image.</p>
<h3 class="relative group flex items-baseline">
	<a id="inside-one-block" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#inside-one-block" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Inside one block
	</span>
</h3>
<p>Every block, in either stage, has the same shape. Attention and the MLP run <strong>in parallel</strong> on the same normalized input, and their sum is added back to the residual stream.</p>
<p>Each block starts with a LayerNorm that has no learned scale or shift of its own. The scale, shift, and gate come from a timestep embedding instead (this is called <em>modulation</em>). Inside the attention, the queries and keys are RMS-normalized and get rotary position embeddings (RoPE), which we look at below.</p>
<p>In a joint block, all tokens share the same weights, but text, image, and reference tokens each get their own scale, shift, and gate.</p>
<pre><code class="language-python"><span class="hljs-keyword">def</span> <span class="hljs-title function_">block</span>(<span class="hljs-params">x, shift, scale, gate</span>):      <span class="hljs-comment"># shift, scale, gate come from the token's timestep embedding</span>
    h = layer_norm(x)                  <span class="hljs-comment"># no learned scale or shift</span>
    h = (<span class="hljs-number">1</span> + scale) * h + shift
    q, k, v = to_q(h), to_k(h), to_v(h)
    q, k = rope(rms_norm(q)), rope(rms_norm(k))
    out = attention(q, k, v) + mlp(h)  <span class="hljs-comment"># parallel, MLP is SwiGLU</span>
    <span class="hljs-keyword">return</span> x + gate * out
</code></pre>
<h3 class="relative group flex items-baseline">
	<a id="every-token-gets-its-own-timestep" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#every-token-gets-its-own-timestep" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Every token gets its own timestep
	</span>
</h3>
<p>In FLUX.1 and FLUX.2, one timestep embedding modulates every token. In FLUX.3, the modulation depends on the kind of token.</p>
<p>The noisy image tokens are modulated by the current timestep <code>t</code>. The text and reference tokens are always modulated by timestep <strong>0</strong>, which means "clean, nothing to denoise here". So even a reference that looks almost the same as the output is marked as given context, not as something to generate.</p>
<p>The distilled checkpoint is a <em>flow map</em>. It is also told the timestep each step jumps to. That second timestep gets its own embedding, which is added to every token's modulation, so each of its 16 steps can make a larger jump.</p>
<h3 class="relative group flex items-baseline">
	<a id="positions-in-four-dimensions" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#positions-in-four-dimensions" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Positions in four dimensions
	</span>
</h3>
<p>Attention on its own doesn't know where a token is (this phenomenon is called permutation equivariance). RoPE fixes that by rotating each query and key by an amount that depends on the token's position. FLUX.3 uses four position axes, <code>(t, h, w, l)</code> (timestep, height, width, length of sequence), and gives each one a quarter (32 dimensions) of every 128-dimensional attention head:</p>

<p>Text tokens line up along <code>l</code>, like words in a sentence. The image and the references are 2D grids in <code>(h, w)</code>, separated from each other along <code>l</code>. Because a reference uses the same <code>(h, w)</code> coordinates as the output, "the same spot in the reference" has a precise meaning to the model, which is what the <code>src_bbox</code> / <code>tgt_bbox</code> editing relies on.</p>
<h3 class="relative group flex items-baseline">
	<a id="the-denoising-loop" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#the-denoising-loop" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		The denoising loop
	</span>
</h3>
<p>FLUX.3 is a flow-matching model. Generation starts from pure noise, and at each of the 50 steps the transformer predicts a <em>velocity</em>. This is the direction from noise toward a clean image. The scheduler takes one step along it.</p>
<p>At every step you can also read off the model's current guess of the final image. Decoding that guess at a few steps shows how the image takes shape:</p>

<h2 class="relative group flex items-baseline">
	<a id="modular-diffusers" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#modular-diffusers" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Modular Diffusers
	</span>
</h2>
<p>FLUX.3 ships as a <a href="https://huggingface.co/docs/diffusers/main/en/modular_diffusers/overview">Modular Diffusers</a> pipeline.</p>
<h3 class="relative group flex items-baseline">
	<a id="see-the-workflows" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#see-the-workflows" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		See the workflows
	</span>
</h3>
<p>You can list the workflows and print the exact blocks of each one, without loading any weights.</p>
<pre><code class="language-python"><span class="hljs-keyword">from</span> diffusers <span class="hljs-keyword">import</span> Flux3AutoBlocks

blocks = Flux3AutoBlocks()
<span class="hljs-built_in">print</span>(blocks.available_workflows)
<span class="hljs-comment"># ['text2image', 'image_conditioned']</span>

<span class="hljs-built_in">print</span>(<span class="hljs-built_in">list</span>(blocks.get_workflow(<span class="hljs-string">"text2image"</span>).sub_blocks))
<span class="hljs-comment"># ['text_encoder', 'denoise.input', 'denoise.prepare_latents', 'denoise.set_timesteps',</span>
<span class="hljs-comment">#  'denoise.prepare_rope_inputs', 'denoise.denoise', 'denoise.after_denoise', 'decode']</span>
</code></pre>
<p><code>get_workflow()</code> resolves the auto branches and gives you the plain sequence of steps that will run. <code>print(blocks.get_workflow("image_conditioned").doc)</code> prints the components, inputs, defaults, and outputs of that workflow.</p>
<h3 class="relative group flex items-baseline">
	<a id="encode-once-generate-many" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#encode-once-generate-many" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Encode once, generate many
	</span>
</h3>
<p>Pop the text encoder out, encode the prompt once, free it, and generate from the cached embeddings.</p>
<pre><code class="language-python"><span class="hljs-keyword">import</span> torch
<span class="hljs-keyword">from</span> diffusers <span class="hljs-keyword">import</span> ModularPipeline

model_id = <span class="hljs-string">"black-forest-labs/flux-3-image-klein-base"</span>

blocks = ModularPipeline.from_pretrained(model_id).blocks
text_blocks = blocks.sub_blocks.pop(<span class="hljs-string">"text_encoder"</span>)  <span class="hljs-comment"># `blocks` now starts at the VAE encoder</span>

text_pipe = text_blocks.init_pipeline(model_id)
text_pipe.load_components(dtype=torch.bfloat16)
text_pipe.to(<span class="hljs-string">"cuda"</span>)

state = text_pipe(prompt=prompt, negative_prompt=<span class="hljs-string">""</span>)  <span class="hljs-comment"># no guider here, so ask for the negative embeddings</span>

prompt_embeds = state.get(<span class="hljs-string">"prompt_embeds"</span>)
negative_prompt_embeds = state.get(<span class="hljs-string">"negative_prompt_embeds"</span>)

<span class="hljs-keyword">del</span> text_pipe
torch.cuda.empty_cache()

image_pipe = blocks.init_pipeline(model_id)  <span class="hljs-comment"># no text encoder to load</span>
image_pipe.load_components(dtype={<span class="hljs-string">"vae"</span>: torch.float32, <span class="hljs-string">"default"</span>: torch.bfloat16})
image_pipe.to(<span class="hljs-string">"cuda"</span>)

<span class="hljs-keyword">for</span> seed <span class="hljs-keyword">in</span> <span class="hljs-built_in">range</span>(<span class="hljs-number">3</span>):
    image = image_pipe(
        prompt_embeds=prompt_embeds,
        negative_prompt_embeds=negative_prompt_embeds,
        generator=torch.Generator().manual_seed(seed),
        output=<span class="hljs-string">"images"</span>,
    )[<span class="hljs-number">0</span>]
    image.save(<span class="hljs-string">f"<span class="hljs-subst">{seed}</span>.png"</span>)
</code></pre>
<h3 class="relative group flex items-baseline">
	<a id="add-a-step-inside-the-loop" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#add-a-step-inside-the-loop" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Add a step inside the loop
	</span>
</h3>
<p>The denoising figure above came from one extra block that records the model's guess of the clean image at every step:</p>
<pre><code class="language-python"><span class="hljs-keyword">from</span> diffusers.modular_pipelines <span class="hljs-keyword">import</span> Flux3AutoBlocks, InputParam, ModularPipelineBlocks, OutputParam


<span class="hljs-keyword">class</span> <span class="hljs-title class_">Flux3PreviewStep</span>(<span class="hljs-title class_ inherited__">ModularPipelineBlocks</span>):
    model_name = <span class="hljs-string">"flux3"</span>

<span class="hljs-meta">    @property</span>
    <span class="hljs-keyword">def</span> <span class="hljs-title function_">inputs</span>(<span class="hljs-params">self</span>):
        <span class="hljs-keyword">return</span> [InputParam(<span class="hljs-string">"latents"</span>), InputParam(<span class="hljs-string">"noise_pred"</span>)]

<span class="hljs-meta">    @property</span>
    <span class="hljs-keyword">def</span> <span class="hljs-title function_">intermediate_outputs</span>(<span class="hljs-params">self</span>):
        <span class="hljs-keyword">return</span> [OutputParam(<span class="hljs-string">"x0_previews"</span>, type_hint=<span class="hljs-built_in">list</span>)]

<span class="hljs-meta">    @torch.no_grad()</span>
    <span class="hljs-keyword">def</span> <span class="hljs-title function_">__call__</span>(<span class="hljs-params">self, components, block_state, i, t</span>):
        <span class="hljs-keyword">if</span> i == <span class="hljs-number">0</span>:
            block_state.x0_previews = []
        sigma = t / <span class="hljs-number">1000</span>  <span class="hljs-comment"># timesteps are sigmas scaled to [0, 1000]</span>
        block_state.x0_previews.append(block_state.latents - sigma * block_state.noise_pred)  <span class="hljs-comment"># x0 = x_t - sigma * v</span>
        <span class="hljs-keyword">return</span> components, block_state


blocks = Flux3AutoBlocks()
denoise_loop = blocks.sub_blocks[<span class="hljs-string">"denoise"</span>].sub_blocks[<span class="hljs-string">"text2image"</span>].sub_blocks[<span class="hljs-string">"denoise"</span>]
denoise_loop.sub_blocks.insert(<span class="hljs-string">"preview"</span>, Flux3PreviewStep(), <span class="hljs-number">1</span>)  <span class="hljs-comment"># between "denoiser" and "after_denoiser"</span>

pipe = blocks.init_pipeline(model_id)
pipe.load_components(dtype={<span class="hljs-string">"vae"</span>: torch.float32, <span class="hljs-string">"default"</span>: torch.bfloat16})
pipe.to(<span class="hljs-string">"cuda"</span>)

out = pipe(prompt=prompt, generator=torch.Generator().manual_seed(<span class="hljs-number">0</span>), output=[<span class="hljs-string">"x0_previews"</span>, <span class="hljs-string">"images"</span>])
</code></pre>
