<p><!--[--><!--[0--><div class="absolute -left-12 bottom-0 top-0 z-30 not-prose hidden lg:block"><div class="sticky top-4 flex"><div class="h-7 pt-[0.175rem]"><span class="peer" tabindex="0"><button class="select-none text-gray-400 hover:cursor-pointer hover:text-gray-800 dark:text-gray-500 dark:hover:text-gray-400"> <!----></button></span> <div class="invisible w-0 -translate-x-8 -translate-y-6 overflow-hidden rounded-xl border bg-white transition-transform hover:visible hover:w-52 hover:translate-x-0 peer-focus-within:visible peer-focus-within:w-52 peer-focus-within:translate-x-0"> </div></div></div></div><!--]--><!--]-->Modernizing enterprise applications is one of the largest and most expensive software engineering activities organizations undertake. Teams migrate applications across frameworks to improve maintainability, cloud readiness, developer productivity, and access to modern capabilities.</p>
<p>Recent advances in coding agents have sparked excitement around AI-assisted modernization. But an important question remains:</p>
<p><strong>Can AI agents reliably modernize real-world enterprise applications?</strong></p>
<p>Existing software engineering benchmarks have demonstrated impressive progress in bug fixing and code generation, but framework migration presents a fundamentally different challenge. Success requires not only translating code, but also preserving behavior, adapting build systems, and navigating runtime dependencies.</p>
<p>To address this gap, we introduce <strong>ScarfBench (Self-Contained Application Refactoring Benchmark)</strong>, an open benchmark for evaluating AI agents on cross-framework migration tasks in Enterprise Java.</p>
<p>ScarfBench focuses on migrations across three major Java ecosystems:</p>
<ul>
<li>Spring</li>
<li>Jakarta EE</li>
<li>Quarkus</li>
</ul>
<p>Unlike traditional benchmarks that compare generated code against reference implementations, ScarfBench evaluates whether migrated applications actually build, deploy, and preserve behavior.</p>
<h2 class="relative group flex items-baseline">
	<a id="why-migration-is-hard" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#why-migration-is-hard" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Why Migration Is Hard
	</span>
</h2>
<p>Framework migration is much more than replacing annotations.</p>
<p>A simple repository migration can require changes across dependency injection, persistence configuration, queries, and framework descriptors. Small mistakes in any of these pieces can prevent successful deployment.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/3LDxVMx4nf_WEqEN2AQ7W.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/3LDxVMx4nf_WEqEN2AQ7W.png" alt="scarf-intro-anatomy"></a></p>
<p align="center"><b>Figure: Spring → Jakarta Migration Example</b></p>

<p align="center">Framework migration requires translating framework semantics, not just source code.</p>

<h2 class="relative group flex items-baseline">
	<a id="introducing-scarfbench" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#introducing-scarfbench" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Introducing ScarfBench
	</span>
</h2>
<p><a href="https://huggingface.co/spaces/ibm-research/ScarfBench">ScarfBench</a> provides a systematic way to evaluate AI agents on enterprise Java framework migration tasks.</p>
<p>Applications are required to:</p>
<ol>
<li>Build successfully.</li>
<li>Deploy correctly.</li>
<li>Pass behavioral validation.</li>
</ol>
<p>This provides a much more realistic measure of modernization quality.</p>

<h2 class="relative group flex items-baseline">
	<a id="how-do-frontier-agents-perform" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#how-do-frontier-agents-perform" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		How Do Frontier Agents Perform?
	</span>
</h2>
<p>We evaluated several state-of-the-art coding agents on ScarfBench.</p>
<p>Despite strong performance on traditional software engineering benchmarks, framework migration remains difficult. Success rates vary considerably across framework pairs and whole-application migrations remain particularly challenging.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/MrcQ5trSi8oKtfD2UEhm9.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/MrcQ5trSi8oKtfD2UEhm9.png" alt="leaderboard"></a></p>
<p align="center"><b>Figure: Current Leaderboard</b></p>
<div style="text-align: center;">
  Source:
<a href="https://scarfbench.info/leaderboard" style="color: #2563eb; text-decoration: underline;" rel="nofollow">
  scarfbench.info/leaderboard
</a>
</div>
Even the strongest current agents achieve less than 10% behavioral success, illustrating the gap between generating compilable code and preserving application behavior.

<p><a href="https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/j7rihRrFe-Eo9oSxNFQS1.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/j7rihRrFe-Eo9oSxNFQS1.png" alt="scarf_aggregate_progression"></a></p>
<p align="center"><b>Figure: Compile → Deploy → Test Progression</b></p>

<p align="center">Compile success consistently exceeds deploy success, which in turn exceeds behavioral success. Build success alone significantly overestimates migration quality.</p>


<p><a href="https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/mQhC1EtAb5dx2Q8d5nqmL.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/mQhC1EtAb5dx2Q8d5nqmL.png" alt="sankey"></a></p>
<p align="center"><b>Figure: Migration Outcomes by Target Framework</b></p>

<p align="center">Migration difficulty depends strongly on the target framework, with Jakarta EE proving particularly challenging.</p>

<h2 class="relative group flex items-baseline">
	<a id="what-we-learned-about-ai-agents-for-java-modernization" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#what-we-learned-about-ai-agents-for-java-modernization" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		What We Learned About AI Agents for Java Modernization
	</span>
</h2>
<p>Beyond measuring success rates, ScarfBench helps us understand how agents behave during modernization.</p>
<h3 class="relative group flex items-baseline">
	<a id="can-agents-reliably-tell-when-a-migration-is-complete" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#can-agents-reliably-tell-when-a-migration-is-complete" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Can Agents Reliably Tell When a Migration Is Complete?
	</span>
</h3>
<p>A migrated application is only useful if it actually builds and runs.</p>
<p>We therefore compared agent-reported outcomes against independent build verification.</p>
<h4 class="relative group flex items-baseline">
	<a id="finding-agents-are-overconfident" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#finding-agents-are-overconfident" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Finding: Agents Are Overconfident
	</span>
</h4>
<p>Claude Code reported successful builds for 29 out of 30 whole applications.</p>
<p>Only 22 of those applications actually built successfully.</p>
<p>Meanwhile, the single application classified as failed by the agent ultimately built correctly.</p>
<p>This suggests that agent self-assessment should not be treated as a reliable signal of migration completion.</p>
<p>Independent build and test validation remains essential.</p>
<h3 class="relative group flex items-baseline">
	<a id="how-do-agents-navigate-application-dependencies" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#how-do-agents-navigate-application-dependencies" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		How Do Agents Navigate Application Dependencies?
	</span>
</h3>
<p>Framework migrations rarely affect a single file or layer.</p>
<p>Changes in configuration, services, databases, and web components often cascade across the application.</p>
<h4 class="relative group flex items-baseline">
	<a id="finding-migration-is-iterative-rather-than-linear" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#finding-migration-is-iterative-rather-than-linear" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Finding: Migration Is Iterative Rather Than Linear
	</span>
</h4>
<p>The most frequently visited layers were:</p>
<ul>
<li>Configuration</li>
<li>Web</li>
<li>Database</li>
<li>Service</li>
</ul>
<p>Common transitions included:</p>
<ul>
<li>Configuration ↔ Web</li>
<li>Service ↔ Database</li>
</ul>
<p>This suggests that migration is an iterative dependency-resolution process rather than a simple source-to-source transformation.</p>
<h3 class="relative group flex items-baseline">
	<a id="where-do-agents-spend-most-of-their-effort" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#where-do-agents-spend-most-of-their-effort" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Where Do Agents Spend Most of Their Effort?
	</span>
</h3>
<p>We used layer revisit frequency as a proxy for migration effort. Layers that required repeated visits typically involved debugging, dependency resolution, or framework adaptation.</p>
<h4 class="relative group flex items-baseline">
	<a id="finding-configuration-dominates-migration-effort" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#finding-configuration-dominates-migration-effort" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Finding: Configuration Dominates Migration Effort
	</span>
</h4>
<p>Rather than proceeding linearly, agents repeatedly returned to configuration-related artifacts while resolving framework differences and dependency issues.</p>
<h3 class="relative group flex items-baseline">
	<a id="what-challenges-are-not-about-code-transformation" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#what-challenges-are-not-about-code-transformation" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		What Challenges Are Not About Code Transformation?
	</span>
</h3>
<p>Not every migration issue originates from source code.</p>
<h4 class="relative group flex items-baseline">
	<a id="finding-environment-and-tooling-matter" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#finding-environment-and-tooling-matter" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Finding: Environment and Tooling Matter
	</span>
</h4>
<p>Agents frequently struggled with environmental issues, including:</p>
<ul>
<li>Docker cache inconsistencies</li>
<li>Port connectivity problems</li>
<li>Maven wrapper and build tooling issues</li>
</ul>
<p>These operational concerns often delayed validation even when the source-code migration itself was largely complete.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/BtWLPGsif0O4VoQfVppIC.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/BtWLPGsif0O4VoQfVppIC.png" alt="failure-distribution"></a></p>
<p align="center"><b>Figure: Failure Mode Distribution</b></p>

<p align="center">Modernization failures span build systems, deployment environments, dependency injection, databases, endpoints, assertions, and infrastructure.</p>

<h2 class="relative group flex items-baseline">
	<a id="key-takeaway" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#key-takeaway" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Key Takeaway
	</span>
</h2>
<p>The biggest challenge in framework modernization is not translating Java code.</p>
<p>It is managing the web of dependencies across configuration, infrastructure, and runtime environments.</p>
<p>While frontier agents can automate substantial portions of the migration process, reliable validation and architectural reasoning remain critical for achieving successful outcomes.</p>
<p>ScarfBench helps expose these challenges and provides a standardized way to measure progress toward truly autonomous application modernization.</p>
<h2 class="relative group flex items-baseline">
	<a id="explore-scarfbench" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#explore-scarfbench" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Explore ScarfBench
	</span>
</h2>
<p>ScarfBench is designed as an open resource for researchers and practitioners.</p>
<p>Resources include:</p>
<ul>
<li>Benchmark dataset</li>
<li>Evaluation infrastructure</li>
<li>Public leaderboard</li>
<li>Documentation</li>
<li>Open-source code</li>
</ul>
<p>Researchers can compare agent architectures and techniques. Practitioners can use ScarfBench to evaluate modernization solutions before deploying them in production environments.</p>
