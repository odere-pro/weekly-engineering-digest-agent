<p><!--[--><!--[0--><div class="absolute -left-12 bottom-0 top-0 z-30 not-prose hidden lg:block"><div class="sticky top-4 flex"><div class="h-7 pt-[0.175rem]"><span class="peer" tabindex="0"><button class="select-none text-gray-400 hover:cursor-pointer hover:text-gray-800 dark:text-gray-500 dark:hover:text-gray-400"> <!----></button></span> <div class="invisible w-0 -translate-x-8 -translate-y-6 overflow-hidden rounded-xl border bg-white transition-transform hover:visible hover:w-52 hover:translate-x-0 peer-focus-within:visible peer-focus-within:w-52 peer-focus-within:translate-x-0"> </div></div></div></div><!--]--><!--]--><a href="https://cdn-uploads.huggingface.co/production/uploads/68127936de624fb6f57d9989/6ORCRF3ze_mI5BYb6hh9u.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/68127936de624fb6f57d9989/6ORCRF3ze_mI5BYb6hh9u.png" alt="newsletter-speech-ai-customer-600x600 (4)"></a></p>
<p>Every voice interaction has a latency budget.</p>
<p>By the time a user hears your application respond, you've already spent precious milliseconds capturing audio, transcribing speech, running an LLM, retrieving context, and generating a response. Text-to-speech (TTS) is the final step — and the one users notice most. If speech generation is slow, the whole experience feels slow.</p>
<p>The more of that pipeline you can run and tune yourself, the more of the latency budget you get back.</p>
<p>Voice AI is moving fast. Integrated speech models offer simplicity — one API call, audio in, audio out — but they trade the ability to fine-tune each component for your domain, swap in better models as they ship, enforce data residency, and understand exactly where latency is coming from. For more control, a cascaded architecture — purpose-built ASR, TTS, and LLM components running together — keeps each layer independently tunable and deployable on infrastructure you own.</p>
<p><a href="https://huggingface.co/nvidia/magpie_tts_multilingual_357m">NVIDIA Magpie Multilingual TTS</a> is built for that. With open weights, <a href="https://build.nvidia.com/nvidia/magpie-tts-multilingual" rel="nofollow">production-ready NVIDIA NIM</a>, and support for 12 languages, you can deploy multilingual speech inside your own infrastructure, optimize latency for your workload, and customize the model for your domain — end to end, in your own environment.</p>
<p>The latest release expands multilingual coverage with Modern Standard Arabic, Korean, and Brazilian Portuguese, while improving quality across many existing languages through updated training data and model improvements.</p>
<p>Whether you're building customer support agents, healthcare assistants, enterprise copilots, translation systems, or conversational AI applications, Magpie provides an open foundation for production voice AI.</p>
<h2 class="relative group flex items-baseline">
	<a id="voice-ai-is-becoming-multilingual-by-default" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#voice-ai-is-becoming-multilingual-by-default" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Voice AI Is Becoming Multilingual by Default
	</span>
</h2>
<p>Today's voice applications don't serve a single language.</p>
<p>Global customer support, enterprise assistants, healthcare documentation, retail automation, and translation workflows increasingly require natural conversations across multiple languages — all while maintaining low latency.</p>
<p>Supporting more languages is only part of the challenge. Developers also need the ability to:</p>
<ul>
<li>Deploy where their data lives  </li>
<li>Meet enterprise privacy requirements  </li>
<li>Customize pronunciation and voices  </li>
<li>Predict latency under production workloads  </li>
<li>Scale on their own infrastructure</li>
</ul>
<p><strong>Open models change what's possible on every one of these.</strong></p>
<h2 class="relative group flex items-baseline">
	<a id="one-open-model-twelve-languages" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#one-open-model-twelve-languages" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		One Open Model, Twelve Languages
	</span>
</h2>
<p>Magpie TTS Multilingual is a 364M-parameter open-weights model supporting:</p>
<p>English · Spanish · French · German · Italian · Vietnamese · Mandarin · Hindi · Japanese · Modern Standard Arabic (new) · Korean (new) · Brazilian Portuguese (new)</p>
<p>Each language includes male and female speaker voices through a shared multilingual speaker representation.</p>
<p>This release also improves multilingual flexibility with expanded code-switching support for Hindi and Japanese, enabled through IPA grapheme-to-phoneme processing and custom pronunciation dictionaries — making it easier to accurately pronounce names, technical terminology, and mixed-language content.</p>
<p>Instead of maintaining separate TTS models for different regions, developers can build multilingual applications on a single open foundation.</p>
<h2 class="relative group flex items-baseline">
	<a id="the-latency-your-users-actually-notice" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#the-latency-your-users-actually-notice" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		The Latency Your Users Actually Notice
	</span>
</h2>

The open Hugging Face checkpoint is the same model and your path for research and fine-tuning; the NIM is the tuned serving stack that produces these production latencies. Both run on hardware you control.</p>
<p>Because the model runs on your own infrastructure, you can benchmark performance directly, tune it for your deployment, and scale according to your workload. For real-time voice agents, that's the difference between conversations that feel responsive and conversations that feel delayed.</p>
<h2 class="relative group flex items-baseline">
	<a id="optimized-for-real-time-speech-generation" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#optimized-for-real-time-speech-generation" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Optimized for Real-Time Speech Generation
	</span>
</h2>
<p>Low latency isn't accidental. Magpie introduces two complementary architectural improvements that reduce inference time while maintaining speech quality.</p>
<p><strong>Frame stacking.</strong> The decoder predicts two audio frames during each decoding step rather than one. This cuts the number of decoder iterations in half, shortening generation time and improving throughput.</p>
<p><strong>Local transformer.</strong> Frame stacking alone would reduce audio quality by introducing dependencies between simultaneously generated codebook tokens. The local transformer models those dependencies and refines the generated audio, recovering the quality that frame stacking would otherwise sacrifice.</p>
<p>Together, these techniques deliver both faster generation and natural speech synthesis. The architecture is described in <a href="https://arxiv.org/abs/2509.19592" rel="nofollow">Frame-Stacked Local Transformers for Efficient Multi-Codebook Speech Generation</a> (ICASSP 2026).</p>

<h2 class="relative group flex items-baseline">
	<a id="why-open-weights-matter" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#why-open-weights-matter" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Why Open Weights Matter
	</span>
</h2>
<p>Latency you can measure is useful. Latency you can control is even better.</p>
<p>Open weights give developers capabilities that come from owning the deployment. With Magpie you can:</p>
<ul>
<li><strong>Deploy on infrastructure you control</strong> — run entirely within your own infrastructure, including private or air-gapped environments.  </li>
<li><strong>Own your latency budget</strong> — no managed-service round-trip, and you optimize directly for your hardware and workload.  </li>
<li><strong>Customize pronunciation and voices</strong> — fine-tune with NeMo for your own brand, domain vocabulary, or speaker data.  </li>
<li><strong>Scale on your own terms</strong> — optimize the serving stack for your infrastructure and workload.</li>
<li><strong>Maintain enterprise control</strong> — keep sensitive conversations and customer data inside your environment.</li>
</ul>
<p>For enterprises building production voice AI, this control over deployment, performance, and customization is often what matters most.</p>
<h2 class="relative group flex items-baseline">
	<a id="build-complete-voice-agents--not-just-better-speech" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#build-complete-voice-agents--not-just-better-speech" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Build Complete Voice Agents — Not Just Better Speech
	</span>
</h2>
<p>Voice AI in production is a system of models, not a single one. Magpie TTS is part of the <a href="https://build.nvidia.com/nvidia/nemotron-voice-agent" rel="nofollow">NVIDIA Nemotron Voice Agent Developer Example</a>, a reference implementation showing how purpose-built speech, language, and reasoning models work together as a coordinated system — so you can build always-on voice agents, not just better-sounding speech.</p>
<p>Developers can combine:</p>
<ul>
<li>Nemotron Speech for streaming speech recognition  </li>
<li>Magpie TTS for natural multilingual speech synthesis  </li>
<li>Nemotron language and multimodal models for reasoning, tool calling, and multimodal understanding  </li>
<li>NVIDIA NIM for GPU-optimized, production-ready inference microservices  </li>
<li>NeMo for customization and fine-tuning</li>
</ul>
<p>The Nemotron Voice Agent developer example provides an end-to-end reference implementation that developers can clone, customize, and deploy in hours. It includes production patterns for:</p>
<ul>
<li>Real-time interruptible (barge-in) conversations  </li>
<li>Multimodal voice agents with vision understanding  </li>
<li>Multi-agent orchestration and tool calling  </li>
<li>Multilingual voice interactions  </li>
<li>Sub-second end-to-end latency using NVIDIA NIM</li>
</ul>
<p>Rather than assembling individual components from scratch, developers can start from a complete reference architecture and adapt it to their own applications.</p>
