<p><!--[--><!--[0--><div class="absolute -left-12 bottom-0 top-0 z-30 not-prose hidden lg:block"><div class="sticky top-4 flex"><div class="h-7 pt-[0.175rem]"><span class="peer" tabindex="0"><button class="select-none text-gray-400 hover:cursor-pointer hover:text-gray-800 dark:text-gray-500 dark:hover:text-gray-400"> <!----></button></span> <div class="invisible w-0 -translate-x-8 -translate-y-6 overflow-hidden rounded-xl border bg-white transition-transform hover:visible hover:w-52 hover:translate-x-0 peer-focus-within:visible peer-focus-within:w-52 peer-focus-within:translate-x-0"> </div></div></div></div><!--]--><!--]--><a href="https://cdn-uploads.huggingface.co/production/uploads/68642da9885da181fde1ad70/mlI168havBLGXY2qbd4ud.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/68642da9885da181fde1ad70/mlI168havBLGXY2qbd4ud.png" alt="AutoSynthData_thumbnail_1200x648 (2)"></a></p>
<p>Enterprises need agents that work well in their own environments. The work they ask these agents to do is shaped by the systems they use, the rules they follow, and the state of their data. A model may be broadly capable and still struggle with a particular environment: a workflow it handles poorly, a combination of tools it misuses, or a constraint it fails to respect. Those are the weaknesses an enterprise needs to improve.</p>
<p>The difficulty is turning those weaknesses into training data. An individual failure tells us something, but training a model requires many new tasks that exercise the same capability in different situations. Those tasks must also be possible to complete in the environment, resemble work someone would actually request, and have a reliable way to check whether the agent succeeded.</p>
<p>At ServiceNow CoreAI, we built AutoSynthData to turn those capability gaps into training data. It uses a target model’s failures and a stronger teacher’s successes to decide what the model should learn next, then generates and validates new tasks that exercise those capabilities. As the model improves, the curriculum shifts toward what it still finds difficult. We illustrate the pipeline with EnterpriseOps Gym (<a href="https://arxiv.org/abs/2603.13594" rel="nofollow">Malay et al., 2026</a>), using the <a href="https://huggingface.co/datasets/ServiceNow-AI/EnterpriseOps-Gym">released dataset</a>. We begin by describing the environment an agent operates in and what makes a task useful for training.</p>
<h2 class="relative group flex items-baseline">
	<a id="what-makes-a-useful-agentic-task" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#what-makes-a-useful-agentic-task" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		What makes a useful agentic task?
	</span>
</h2>
<p>An agentic environment defines the world in which an agent operates: the state it can observe and modify, the tools and APIs it can invoke, and the state transitions produced by its actions.</p>
<p>A task is instantiated within this environment. We use the following abstraction:</p>
<pre><code class="language-text">task = (system specification, user prompt, verifier)
</code></pre>
<h3 class="relative group flex items-baseline">
	<a id="system-specification" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#system-specification" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		System specification
	</span>
</h3>
<p>The system specification defines the constraints under which the agent operates, including system instructions, environment policies, and, when applicable, task-specific initialization such as a seeded database state or a set of knowledge articles.</p>
<p>The specification must be compatible with the environment’s tools, state, and supported actions. Its instructions should be clear and avoid arbitrary constraints introduced solely to manufacture difficulty.</p>
<h3 class="relative group flex items-baseline">
	<a id="agent-facing-task" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#agent-facing-task" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Agent-facing task
	</span>
</h3>
<p>The user prompt specifies what the user wants the agent to accomplish, together with any user-level constraints. A generated task should satisfy three properties.</p>
<p><strong>Feasibility.</strong> There should exist at least one trajectory in the current environment that satisfies the user prompt while respecting the system specification. This rules out tasks that depend on unavailable tools, inaccessible knowledge, impossible state transitions, or actions prohibited by policy.</p>
<p><strong>Realism.</strong> The user prompt should resemble something a user would plausibly ask in the target environment. The space of executable behaviors is usually much larger than the space of realistic workflows.</p>
<p><strong>Difficulty.</strong> For training, the task should expose a weakness of the current agent. Tasks that are already solved reliably provide little new training signal. The useful region is therefore tasks that are feasible and realistic, but not yet consistently solved.</p>
<h3 class="relative group flex items-baseline">
	<a id="verifier" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#verifier" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Verifier
	</span>
</h3>
<p>The verifier determines whether the resulting trajectory successfully completes the task. It should satisfy three properties.</p>
<p><strong>Consistency.</strong> It should agree with the user prompt, the system specification, and the task-specific environment state.</p>
<p><strong>Soundness.</strong> It should reject trajectories that fail to satisfy the task or violate relevant constraints.</p>
<p><strong>Completeness.</strong> It should accept valid solutions rather than encode one particular reference trajectory.</p>
<p>These properties matter directly during training. A lax verifier can reward incorrect behavior, while an overly restrictive verifier can penalize valid solutions.</p>
<h2 class="relative group flex items-baseline">
	<a id="overview" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#overview" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Overview
	</span>
</h2>
<p>Given an environment and a target model, AutoSynthData generates training tasks consisting of a system specification, user prompt, and verifier. The generated tasks are grounded in the environment and selected to provide useful training signal for the current model.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/sM50frTSx9Q7Yyh6UNcGz.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/sM50frTSx9Q7Yyh6UNcGz.png" alt="figure-01"></a></p>
<p>AutoSynthData first evaluates the target model in the environment using diagnostic tasks and identifies patterns in the tasks it struggles to complete. A stronger teacher helps characterize which of those tasks are solvable and what successful behavior looks like. AutoSynthData turns the resulting capability gaps into new executable tasks, checks each task in the environment, and uses accepted samples for post-training. Evaluating the updated model reveals which gaps remain and can guide the next round of generation.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/huMlVCBcc-IseCIk5uEIJ.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/huMlVCBcc-IseCIk5uEIJ.png" alt="figure-02"></a></p>
<h2 class="relative group flex items-baseline">
	<a id="from-model-failures-to-a-curriculum" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#from-model-failures-to-a-curriculum" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		From model failures to a curriculum
	</span>
</h2>
<p>AutoSynthData uses evaluation runs in the target environment to identify what the model needs to learn next. In our EnterpriseOps Gym experiment, we run both the target model and a stronger teacher on the evaluation tasks. We examine those runs to identify:</p>
<ul>
<li>the capability being tested;</li>
<li>the tools and workflow structure involved;</li>
<li>where the target model fails and how the teacher succeeds;</li>
<li>the properties that a correct final state must satisfy;</li>
<li>the dimensions that can vary while preserving the capability being tested.</li>
</ul>
<p>We distill these findings into sanitized capability specification cards. The evaluation tasks guide what the model should learn, but the generator does not receive their original prompts, entities, trajectories, or verifier details. It receives the cards and uses them to create new tasks with different prompts, states, and solution paths.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/ZwShYC2FDYFXU9yR9yz1t.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/ZwShYC2FDYFXU9yR9yz1t.png" alt="figure-03"></a></p>
<h2 class="relative group flex items-baseline">
	<a id="generating-and-scaling-tasks" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#generating-and-scaling-tasks" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Generating and scaling tasks
	</span>
</h2>
<p>Identifying a capability gap tells us what to teach, but training requires many varied tasks that exercise it. AutoSynthData uses the specification card to generate those tasks.</p>
<p>Suppose the target model struggles with tasks that require the following workflow:</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/UCTRFFZ7ttq6JEXZr5_Qi.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/UCTRFFZ7ttq6JEXZr5_Qi.png" alt="figure-04"></a></p>
<p>The generator creates new tasks that exercise this workflow, varying the entities, initial environment state, workflow composition, tool combinations, wording, and difficulty. The stronger teacher then demonstrates a successful trajectory for each task. For supervised fine-tuning (SFT), these demonstrations teach the target model how to apply the capability in new situations.</p>
<p>AutoSynthData builds the dataset in two phases: first generating and validating core samples, then expanding them into novel variants.</p>
<h3 class="relative group flex items-baseline">
	<a class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#target" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Target
	</span>
</h3>
<p>The target phase creates the core set of training samples from the capability specifications. Workers generate independent tasks in parallel, picking up a new target when they finish. Each candidate goes through validation, execution, solver evaluation, and repair before acceptance. The result is a batch of vetted examples built around what the target model needs to learn.</p>
<h3 class="relative group flex items-baseline">
	<a id="multiply" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#multiply" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Multiply
	</span>
</h3>
<p>The multiply phase expands the dataset by creating novel variants of accepted target samples. Each variant has its own user request, environment state, entity configuration, reference trajectory, and verifier, and must pass the same validation and execution checks. A multiplied sample cannot seed another multiplied sample. This anchors expansion to the vetted target set and limits drift across generations.</p>
<h3 class="relative group flex items-baseline">
	<a id="implementation-details" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#implementation-details" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Implementation details
	</span>
</h3>
<p>To support both phases, AutoSynthData separates generation control from environment-specific execution. A shared controller coordinates generation, quality control, coverage, and dataset construction, while an adapter handles environment execution, task and state management, reference replay, deterministic verification, solver execution, and task profiling.</p>
<p>Together, parallel target generation and multiplication provide a path to training-scale datasets. Their usefulness depends on the checks applied to every candidate: the task must be executable, the solution must work, and the verifier must distinguish success from failure.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/zUTtl1ILl-fTtA-0RZdgV.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/zUTtl1ILl-fTtA-0RZdgV.png" alt="figure-05"></a></p>
<h2 class="relative group flex items-baseline">
	<a id="high-quality-synthetic-data-needs-more-than-generation" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#high-quality-synthetic-data-needs-more-than-generation" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		High-quality synthetic data needs more than generation
	</span>
</h2>
<p>Generating a plausible request is not enough to produce useful training data. A task may be impossible in the target environment, its reference solution may fail when executed, or its verifier may reward the wrong final state. AutoSynthData checks these properties before accepting a task for training.</p>
<p>AutoSynthData reviews quality at two levels: individual candidates must pass verification, and batches must provide useful coverage and diversity.</p>
<h3 class="relative group flex items-baseline">
	<a id="sample-level-verification-and-repair" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#sample-level-verification-and-repair" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Sample-level verification and repair
	</span>
</h3>
<p>Each candidate must clear a quality-control loop before entering the training dataset. We begin with solver evaluation to measure difficulty. In the configuration used here, we favor tasks the target model solves on no more than one of three trials and the stronger solver solves on at least two of three trials. Candidates also undergo positive and negative verification and a bounded repair process.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/r3nXamYF6OEI2ezj7MX78.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/r3nXamYF6OEI2ezj7MX78.png" alt="figure-06"></a></p>
<h4 class="relative group flex items-baseline">
	<a id="positive-verification" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#positive-verification" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Positive verification
	</span>
</h4>
<p>The positive gate asks: Does the intended solution solve the generated task?</p>
<p>The pipeline executes the reference trajectory in the target environment and checks the resulting state against the candidate’s verifier. This reveals mismatches among the prompt, initial state, solution, and success criteria.</p>
<h4 class="relative group flex items-baseline">
	<a id="negative-verification" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#negative-verification" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Negative verification
	</span>
</h4>
<p>The negative gate asks: Do relevant incorrect outcomes fail?</p>
<p>For example, it can mutate parts of the expected outcome and confirm that those states no longer pass verification. This catches weak verifiers that award success without requiring the intended behavior.</p>
<h4 class="relative group flex items-baseline">
	<a id="critique-and-repair" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#critique-and-repair" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Critique and repair
	</span>
</h4>
<p>Failed candidates go to a critic before being discarded. The critic examines the sample and its failure, looking for inconsistent state, impossible workflows, incorrect task construction, bad reference trajectories, weak verifier logic, or a mismatch with the intended capability. The critic’s findings guide repairs, with a fixed limit on retries:</p>
<pre><code class="language-text">candidate
↓
failure
↓
critique / diagnosis
↓
targeted repair
↓
run the gates again
↓
accept or retry
</code></pre>
<p>A repaired task must pass the relevant checks again. The diagnosis guides repairs to the existing candidate rather than requiring generation to start over.</p>
<p>Passing these checks makes a sample eligible for training, but individually valid samples can still form a repetitive or unbalanced dataset. AutoSynthData therefore also reviews generation at the batch level.</p>
<h3 class="relative group flex items-baseline">
	<a id="batch-level-review" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#batch-level-review" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Batch-level review
	</span>
</h3>
<p>A batch may overrepresent a few easy task families, miss a capability, or reflect too much generation effort spent on a low-yield pattern.</p>
<p>A meta-review examines accepted samples, rejected samples, and generation behavior across each batch. It asks:</p>
<ul>
<li>Which task families are overrepresented, and which capability dimensions are missing?</li>
<li>Are the same kinds of examples appearing repeatedly?</li>
<li>Do particular targets keep failing generation?</li>
<li>Are systematic problems appearing in critiques?</li>
<li>What guidance should change for the next batch?</li>
</ul>
<p>The controller tracks coverage in the accepted dataset, reduces generation in overrepresented regions, and directs more work toward gaps. When a region repeatedly produces poor candidates, critiques and meta-review guide changes to the generation strategy. These adjustments balance useful learning signal, task quality, coverage, diversity, and low redundancy within the available generation budget and dataset size requirements.</p>
<p>Together, these feedback loops improve both individual tasks and the dataset they form: sample-level checks guide candidate repair, while batch-level review guides future generation.</p>
<h2 class="relative group flex items-baseline">
	<a id="moving-the-training-frontier" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#moving-the-training-frontier" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Moving the training frontier
	</span>
</h2>
<p>The useful training distribution changes as the model improves. AutoSynthData treats synthetic data generation as a search for tasks near the target model's capability boundary: difficult enough to expose weaknesses, but solvable enough for the teacher to provide reliable demonstrations.</p>
<p>After post-training, we evaluate the updated model in the same environment. Tasks it now solves reliably are less useful for the next training round; persistent failures point to capabilities that still need attention. Those results can guide the next generation round.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/ONKQXJ1u9buDLEa-AuXMo.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/ONKQXJ1u9buDLEa-AuXMo.png" alt="figure-07"></a></p>
<p>Our experiments focus on SFT, but the same mechanism could support reinforcement learning (RL): generate tasks that challenge the current policy and provide reliable learning signal, train, then move the generation target with the updated policy. We plan to test this moving, difficulty-calibrated frontier beyond SFT.</p>
<h2 class="relative group flex items-baseline">
	<a id="enterpriseops-gym-experiments" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#enterpriseops-gym-experiments" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		EnterpriseOps Gym experiments
	</span>
</h2>
<p>We use EnterpriseOps Gym to test whether this approach improves a model on tasks in a stateful enterprise environment. We generate training tasks in the Gym’s Hybrid and ITSM environments, fine-tune the target model on accepted samples, and evaluate the resulting checkpoints.</p>
<h3 class="relative group flex items-baseline">
	<a id="hybrid" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#hybrid" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Hybrid
	</span>
</h3>
<p>We tested the pipeline on the Hybrid domain of EnterpriseOps Gym using <a href="https://huggingface.co/google/gemma-4-26B-A4B-it">Gemma-4-26B-A4B-it</a> as the target model and <a href="https://huggingface.co/Qwen/Qwen3.8-27B">Qwen3.8-27B</a> as the teacher.</p>
<p>AutoSynthData generated 2,000 synthetic training samples in about 18 hours. We fine-tuned Gemma on this dataset and evaluated the resulting checkpoints on the benchmark. The best checkpoint was epoch 5.</p>
<h3 class="relative group flex items-baseline">
	<a id="hybrid-results" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#hybrid-results" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Hybrid results
	</span>
</h3>
<p>The synthetic SFT checkpoint improves mean Pass@1 by 7.2 percentage points, a 35% relative improvement, and raises verifier success from 63.01% to 68.55%. It closes 59% of the original Pass@1 gap between Gemma and the reference model.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/D2CdcykJInh82mYAMGz3I.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/D2CdcykJInh82mYAMGz3I.png" alt="figure-08"></a></p>
<p>The training tasks were newly generated from capability specifications; the generator did not receive the original evaluation tasks. The result demonstrates improvement in EnterpriseOps Gym Hybrid, the environment used for this experiment.</p>
<h3 class="relative group flex items-baseline">
	<a id="itsm" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#itsm" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		ITSM
	</span>
</h3>
<p>We also applied AutoSynthData to the ITSM domain of EnterpriseOps Gym, using Gemma-4-26B-A4B-it as the target model and <a href="https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash">DeepSeek-V4.1-Flash</a> as the teacher. AutoSynthData generated 1,994 synthetic training samples in 66 hours. Generation took longer than in the subsequent Hybrid run described above, primarily because the ITSM run used a larger teacher model and preceded pipeline optimizations that improved throughput.</p>
<p>On ITSM, synthetic SFT raises mean Pass@1 from 18.77% to 27.18%, showing that the approach also improves performance in a second domain.</p>
<p><a href="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/3G6bJhA0JKZMJdiwfeHYs.png" rel="nofollow"><img src="https://cdn-uploads.huggingface.co/production/uploads/66a41f3c1d52bffc13c285a5/3G6bJhA0JKZMJdiwfeHYs.png" alt="figure-09"></a></p>
<h2 class="relative group flex items-baseline">
	<a id="closing-the-loop" class="block pr-1.5 text-lg md:absolute md:p-1.5 md:opacity-0 md:group-hover:opacity-100 md:right-full" href="#closing-the-loop" rel="nofollow">
		<span class="header-link"> </span>
	</a>
	<span>
		Closing the loop
	</span>
</h2>
<p>The tasks most useful for training depend on both the environment and the model working in it. AutoSynthData uses the model’s failures to choose what to generate, validates new tasks against the environment, and makes those tasks available for post-training. Our EnterpriseOps Gym results show the value of that approach in a controlled setting. As the model changes, the same process can focus on the gaps that remain.</p>
