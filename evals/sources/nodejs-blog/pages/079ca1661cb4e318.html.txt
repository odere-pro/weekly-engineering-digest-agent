            <h3 id="notable-changes"><a href="#notable-changes">Notable Changes</a></h3>
            <h4 id="post-quantum-cryptography-in-nodecrypto">
              <a href="#post-quantum-cryptography-in-nodecrypto"
                >Post-Quantum Cryptography in <code>node:crypto</code></a
              >
            </h4>
            <p>
              OpenSSL 3.5 on 24.x kicked off post-quantum cryptography efforts in Node.js by
              allowing use of NIST&#x27;s post-quantum cryptography standards for future-proofing
              applications against quantum computing threats. The following post-quantum algorithms
              are now available in <code>node:crypto</code>:
            </p>
            <ul>
              <li>
                ML-KEM (FIPS 203, Module-Lattice-Based Key-Encapsulation Mechanism Standard) through
                new <code>crypto.encapsulate()</code> and <code>crypto.decapsulate()</code> methods.
              </li>
              <li>
                ML-DSA (FIPS 204, Module-Lattice-Based Digital Signature Standard) in the existing
                <code>crypto.sign()</code> and <code>crypto.verify()</code> methods.
              </li>
            </ul>
            <p>
              Contributed by Filip Skokan in
              <a href="https://github.com/nodejs/node/pull/59259">#59259</a> and
              <a href="https://github.com/nodejs/node/pull/59491">#59491</a>.
            </p>
            <h3 id="modern-algorithms-in-web-cryptography-api">
              <a href="#modern-algorithms-in-web-cryptography-api"
                >Modern Algorithms in Web Cryptography API</a
              >
            </h3>
            <p>
              The second substantial
              <a href="https://wicg.github.io/webcrypto-modern-algos/"
                >extension to the Web Cryptography API</a
              >
              (<code>globalThis.crypto.subtle</code>) was recently accepted for incubation by WICG.
              The following algorithms and methods from this extension are now available in the
              Node.js Web Cryptography API implementation:
            </p>
            <ul>
              <li>AES-OCB</li>
              <li>ChaCha20-Poly1305</li>
              <li>ML-DSA</li>
              <li>ML-KEM</li>
              <li>SHA-3</li>
              <li>SHAKE</li>
              <li><code>subtle.getPublicKey()</code></li>
              <li><code>SubtleCrypto.supports()</code></li>
              <li>... with more coming in future releases.</li>
            </ul>
            <p>
              Contributed by Filip Skokan in
              <a href="https://github.com/nodejs/node/pull/59365">#59365</a>,
              <a href="https://github.com/nodejs/node/pull/59569">#59569</a>,
              <a href="https://github.com/nodejs/node/pull/59461">#59461</a>, and
              <a href="https://github.com/nodejs/node/pull/59539">#59539</a>.
            </p>
            <h4 id="nodejs-execution-argument-support-in-single-executable-applications">
              <a href="#nodejs-execution-argument-support-in-single-executable-applications"
                >Node.js execution argument support in single executable applications</a
              >
            </h4>
            <p>
              The single executable application configuration now supports additional fields to
              specify Node.js execution arguments and control how they can be extended when the
              application is run.
            </p>
            <ul>
              <li>
                <code>execArgv</code> takes an array of strings for the execution arguments to be
                used.
              </li>
              <li>
                <code>execArgvExtension</code> takes one of the following values:<!-- -->
                <ul>
                  <li>
                    <code>&quot;none&quot;</code>: No additional execution arguments are allowed.
                  </li>
                  <li>
                    <code>&quot;cli&quot;</code>: Additional execution arguments can be provided via
                    a special command-line flag
                    <code>--node-options=&quot;--flag1 --flag2=value&quot;</code> at run time.
                  </li>
                  <li>
                    <code>&quot;env&quot;</code> (default): Additional execution arguments can be
                    provided via the <code>NODE_OPTIONS</code> environment variable at run time.
                  </li>
                </ul>
              </li>
            </ul>
