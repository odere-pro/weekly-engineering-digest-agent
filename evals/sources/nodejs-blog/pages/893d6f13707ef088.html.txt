              <a href="#2025-06-24-version-22170-jod-lts-aduh95"
                >2025-06-24, Version 22.17.0 &#x27;Jod&#x27; (LTS), @aduh95</a

            </h2>
            <h3 id="notable-changes"><a href="#notable-changes">Notable Changes</a></h3>
            <h4 id="️-deprecations"><a href="#️-deprecations">⚠️ Deprecations</a></h4>
            <h5 id="instantiating-nodehttp-classes-without-new">
              <a href="#instantiating-nodehttp-classes-without-new"
                >Instantiating <code>node:http</code> classes
                <strong>without <code>new</code></strong></a
              >
            </h5>
            <p>
              Constructing classes like <code>IncomingMessage</code> or
              <code>ServerResponse</code> without the <code>new</code> keyword is now discouraged.
              This clarifies API expectations and aligns with standard JavaScript behavior. It may
              warn or error in future versions.
            </p>
            <p>
              Contributed by Yagiz Nizipli in
              <a href="https://github.com/nodejs/node/pull/58518">#58518</a>.
            </p>
            <h5 id="optionsshell---in-nodechild_process">
              <a href="#optionsshell---in-nodechild_process"
                ><code>options.shell = &quot;&quot;</code> in <code>node:child_process</code></a
              >
            </h5>
            <p>
              Using an empty string for <code>shell</code> previously had undefined behavior. This
              change encourages explicit choices (e.g., <code>shell: true</code> or a shell path)
              and avoids relying on implementation quirks.
            </p>
            <p>
              Contributed by Antoine du Hamel and Renegade334
              <a href="https://github.com/nodejs/node/pull/58564">#58564</a>.
            </p>
            <h5 id="http2-priority-signaling">
              <a href="#http2-priority-signaling">HTTP/2 priority signaling</a>
            </h5>
            <p>
              The HTTP/2 prioritization API (e.g., <code>stream.priority</code>) is now deprecated
              due to poor real-world support. Applications should avoid using priority hints and
              expect future removal.
            </p>
            <p>
              Contributed by Matteo Collina and Antoine du Hamel
              <a href="https://github.com/nodejs/node/pull/58313">#58313</a>.
            </p>
            <h4 id="-features-graduated-to-stable">
              <a href="#-features-graduated-to-stable">✅ Features graduated to stable</a>
            </h4>
            <h5 id="assertpartialdeepstrictequal">
              <a href="#assertpartialdeepstrictequal"
                ><code>assert.partialDeepStrictEqual()</code></a
              >
            </h5>
            <p>
              This method compares only a subset of properties in deep object comparisons, useful
              for flexible test assertions. Its stabilization means it&#x27;s now safe for general
              use and won&#x27;t change unexpectedly in future releases.
            </p>
            <p>
              Contributed by Ruben Bridgewater in
              <a href="https://github.com/nodejs/node/pull/57370">#57370</a>.
            </p>

            <h4 id="semver-minor-features">
              <a href="#semver-minor-features">Semver-minor features</a>
            </h4>
            <h5 id="-fsfilehandlereadablewebstream-gets-autoclose-option">
              <a href="#-fsfilehandlereadablewebstream-gets-autoclose-option"
                >🔧 <code>fs.FileHandle.readableWebStream</code> gets
                <code>autoClose</code> option</a
              >
            </h5>
            <p>
              This gives developers explicit control over whether the file descriptor should be
              closed when the stream ends. Helps avoid subtle resource leaks.
            </p>
            <p>
              Contributed by James M Snell in
              <a href="https://github.com/nodejs/node/pull/58548">#58548</a>.
            </p>
            <h5 id="-fsdir-now-supports-explicit-resource-management">
              <a href="#-fsdir-now-supports-explicit-resource-management"
                >🔧 <code>fs.Dir</code> now supports
                <strong>explicit resource management</strong></a
              >
            </h5>
            <p>
              This improves ergonomics around async iteration of directories. Developers can now
              manually control when a directory is closed using <code>.close()</code> or with
              <code>Symbol.asyncDispose</code>.
            </p>
            <p>
              Contributed by Antoine du Hamel in
              <a href="https://github.com/nodejs/node/pull/58206">#58206</a>.
            </p>
            <h5 id="-http2-gains-diagnostics-channel-http2serverstreamfinish">
              <a href="#-http2-gains-diagnostics-channel-http2serverstreamfinish"
                >📊 <code>http2</code> gains diagnostics channel:
                <code>http2.server.stream.finish</code></a
              >
            </h5>
            <p>
              Adds observability support for when a stream finishes. Useful for logging, monitoring,
              and debugging HTTP/2 behavior without patching internals.
            </p>
            <p>
              Contributed by Darshan Sen in
              <a href="https://github.com/nodejs/node/pull/58560">#58560</a>.
            </p>
            <h5 id="-permissions-implicit-allow-fs-read-to-entrypoint">
              <a href="#-permissions-implicit-allow-fs-read-to-entrypoint"
                >🔐 Permissions: implicit allow-fs-read to entrypoint</a
              >
            </h5>
            <p>
              Node.js permissions model now allows read access to the entry file by default. It
              makes running permission-restricted apps smoother while preserving security.
            </p>
            <p>
              Contributed by Rafael Gonzaga in
              <a href="https://github.com/nodejs/node/pull/58579">#58579</a>.
            </p>
            <h5 id="-utilstyletext-adds-none-style">
              <a href="#-utilstyletext-adds-none-style"
                >🎨 <code>util.styleText()</code> adds <code>&#x27;none&#x27;</code> style</a
              >
            </h5>
            <p>
              This lets developers remove styling cleanly without hacks. Useful for overriding
              inherited terminal styles when composing styled strings.
            </p>
            <p>
              Contributed by James M Snell in
              <a href="https://github.com/nodejs/node/pull/58437">#58437</a>.
            </p>
