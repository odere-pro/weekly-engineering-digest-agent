            <h1 id="nodejs-v22-to-v24"><a href="#nodejs-v22-to-v24">Node.js v22 to v24</a></h1>
            <div class="index-module__VYslka__alertBox index-module__VYslka__info">
              <span class="index-module__VYslka__title">!</span
              ><span class="index-module__VYslka__content"
                ><p>
                  This article covers a part of the migration from Node.js v22 to v24. The userland
                  migrations team is working on more codemods to help you with the migration.
                </p>
                <p>Missing codemods will be added over time. If you have specific needs.</p>
                <a href="https://github.com/nodejs/userland-migrations/issues/239"
                  ><p>
                    Read this issue to learn where we are in the process and how to manually migrate
                    your code.
                  </p></a
                ></span
              >
            </div>
            <p>
              With the release of
              <a href="https://nodejs.org/blog/release/v24.11.0">Node.js 24.11.0</a>, the Node.js 24
              release line has entered Long-Term Support (LTS) and will continue to receive updates
              through to the end of April 2028.
            </p>
            <p>
              If you are migrating from Node.js 22 LTS, the following summarizes the breaking
              changes that came in
              <a href="https://nodejs.org/blog/release/v23.0.0">Node.js 23.0.0</a> and
              <a href="https://nodejs.org/blog/release/v24.0.0">Node.js 24.0.0</a>.
            </p>
            <h3 id="platform-support"><a href="#platform-support">Platform support</a></h3>
            <p>
              Node.js no longer provides
              <a href="https://nodejs.org/en/download">pre-built binaries</a> for:
            </p>
            <ul>
              <li>32-bit Windows (x86) as of Node.js 23.0.0.</li>
              <li>32-bit Linux on armv7 as of Node.js 24.0.0.</li>
            </ul>
            <p>Pre-built binaries for macOS now require a minimum of macOS 13.5.</p>
            <p>
              Pre-built binaries for Linux on arm64, ppc64le, s390x and x64 continue to be
              compatible with glibc 2.28 and above (no change from Node.js 22).
            </p>
            <p>
              Please refer to
              <a href="#building-nodejs-from-source"
                >additional notes if you are building Node.js from source</a
              >.
            </p>
            <h3 id="breaking-changes"><a href="#breaking-changes">Breaking changes</a></h3>
            <h3 id="openssl-35"><a href="#openssl-35">OpenSSL 3.5</a></h3>
            <p>
              Pre-built binaries of Node.js 24 LTS, or builds using the default build configuration
              options, include OpenSSL 3.5. Node.js 24 LTS uses the default security level from
              OpenSSL 3.5 of <code>2</code>, which means that:
            </p>
            <ul>
              <li>
                RSA, DSA and DH keys shorter than 2048 bits and ECC keys shorter than 224 bits are
                prohibited.
              </li>
              <li>Any cipher suite using RC4 is also prohibited.</li>
            </ul>
            <p>
              If you rely on older keys or weak ciphers, test your workloads against Node.js 24
              builds (or adjust key/cipher choices) before upgrading.
            </p>
            <h3 id="other-behavioral-changes-and-argument-validation">
              <a href="#other-behavioral-changes-and-argument-validation"
                >Other behavioral changes and argument validation</a
              >
            </h3>
            <p>
              The release includes a number of behavior and validation changes (stricter
              <code>fetch()</code> compliance, AbortSignal validation, stream/pipe errors now
              throwing, changes to Buffer behavior, path handling fixes on Windows, test runner
              defaults, and more).
            </p>
            <h3 id="cc-addons"><a href="#cc-addons">C/C++ addons</a></h3>
            <p>
              Addons linking against V8 APIs may need updates for V8 13.6; C++20 support may be
              required where previously C++17 was used. Where possible, prefer NODE-API to reduce
              rebuild churn.
            </p>
            <h3 id="building-nodejs-from-source">
              <a href="#building-nodejs-from-source">Building Node.js from source</a>
            </h3>
            <p>
              If you are building Node.js from source, you may need to update your compiler
              toolchain:
            </p>
            <ul>
              <li>
                For AIX and Linux platforms, the minimum supported version of
                <a href="https://gcc.gnu.org/">gcc</a> is 12.2.
              </li>
              <li>
                For macOS the minimum supported version of
                <a href="https://developer.apple.com/xcode/">Xcode</a> is 16.1.
              </li>
            </ul>
            <p>
              Node.js&#x27; <code>configure</code> script will warn if you attempt to build Node.js
              with a compiler toolchain that does not meet the minimum supported version but will
              not actively prevent you from trying.
            </p>
            <h2 id="available-codemods"><a href="#available-codemods">Available Codemods</a></h2>
            <p>
              Some breaking changes or End of Life (EOL) deprecations in Node.js 23 and 24 have
              associated codemods to help you update your codebase. Below is a list of the available
              codemods for this migration:
            </p>
            <h3 id="crypto-rsa-pss-update">
              <a href="#crypto-rsa-pss-update"><code>crypto-rsa-pss-update</code></a>
            </h3>
            <p>
              In <a href="https://nodejs.org/docs/latest/api/deprecations.html#DEP0154">DEP0154</a>,
              the <code>generateKeyPair</code> and <code>generateKeyPairSync</code> methods in the
              <code>crypto</code> module deprecated the <code>hash</code>, <code>mgf1Hash</code>,
              and <code>saltLength</code> options for the <code>&#x27;rsa-pss&#x27;</code> key type
              in favor of <code>hashAlgorithm</code>, <code>mgf1HashAlgorithm</code>, and
              <code>saltLength</code> respectively.
            </p>
            <p>
              The source code for this codemod can be found in the
              <a
                href="https://github.com/nodejs/userland-migrations/tree/main/recipes/crypto-rsa-pss-update"
                >crypto-rsa-pss-update directory</a
              >.
            </p>
            <p>
              You can find this codemod in the
              <a href="https://app.codemod.com/registry/@nodejs/crypto-rsa-pss-update"
                >Codemod Registry</a
              >.
            </p>

            <p>
              You can find this codemod in the

            <h3 id="fs-access-mode-constants">
              <a href="#fs-access-mode-constants"><code>fs-access-mode-constants</code></a>
            </h3>
            <p>
              The <code>fs</code> module introduced a runtime deprecation for <code>F_OK</code>,
              <code>R_OK</code>, <code>W_OK</code>, and <code>X_OK</code> getters exposed directly
              on <code>node:fs</code>. Get them from <code>fs.constants</code> or
              <code>fs.promises.constants</code> instead.
            </p>
            <p>
              This codemod handles
              <a href="https://nodejs.org/api/deprecations.html#DEP0176">DEP0176</a>.
            </p>
            <p>
              The source code for this codemod can be found in the
              <a
                href="https://github.com/nodejs/userland-migrations/tree/main/recipes/fs-access-mode-constants"
                >fs-access-mode-constants directory</a
              >.
            </p>
            <p>
              You can find this codemod in the
              <a href="https://app.codemod.com/registry/@nodejs/fs-access-mode-constants"
                >Codemod Registry</a
              >.
            </p>

            <h3 id="fs-truncate-fd-deprecation">
              <a href="#fs-truncate-fd-deprecation"><code>fs-truncate-fd-deprecation</code></a>
            </h3>
            <p>
              The
              <a href="https://nodejs.org/api/fs.html#fs_fs_truncate_path_len_callback"
                ><code>fs.truncate</code></a
              >
              function was deprecated (<a href="https://nodejs.org/api/deprecations.html#DEP0081"
                >DEP0081</a

              <a href="https://nodejs.org/api/fs.html#fs_fs_ftruncate_fd_len_callback"
                ><code>fs.ftruncate</code></a
              >
              instead.
            </p>
            <p>
              The source code for this codemod can be found in the
              <a
                href="https://github.com/nodejs/userland-migrations/tree/main/recipes/fs-truncate-fd-deprecation"
                >fs-truncate-fd-deprecation directory</a
              >.
            </p>
            <p>
              You can find this codemod in the
              <a href="https://app.codemod.com/registry/@nodejs/fs-truncate-fd-deprecation"
                >Codemod Registry</a
              >.
            </p>

            <h2 id="what-this-codemod-does">
              <a href="#what-this-codemod-does">What this codemod does</a>
            </h2>
            <ul>
              <li>
                Removes the <code>priority</code> property from <code>http2.connect()</code> call
                options
              </li>
              <li>
                Removes the <code>priority</code> property from <code>session.request()</code> call
                options
              </li>
              <li>Removes entire <code>stream.priority()</code> method call statements</li>
              <li>
                Removes the <code>priority</code> property from <code>client.settings()</code> call
                options
              </li>
              <li>
                Handles both CommonJS (<code>require()</code>) and ESM (<code>import</code>) imports
              </li>
            </ul>

            <h3 id="process-assert-to-node-assert">
              <a href="#process-assert-to-node-assert"
                ><code>process-assert-to-node-assert</code></a
              >
            </h3>
            <p>
              In Node.js v23 the
              <a href="https://nodejs.org/api/deprecations.html#DEP0100">DEP0100</a> deprecation
              reached End-of-Life, and <code>process.assert</code> was removed in favor of using the
              <code>assert</code> module directly. This codemod will help you replace any references
              to <code>process.assert</code> with the appropriate import of the
              <code>assert</code> module and usage of <code>assert()</code>.
            </p>
            <p>
              The source code for this codemod can be found in the
              <a
                href="https://github.com/nodejs/userland-migrations/tree/main/recipes/process-assert-to-node-assert"
                >process-assert-to-node-assert directory</a
              >.
            </p>
            <p>
              You can find this codemod in the
              <a href="https://app.codemod.com/registry/@nodejs/process-assert-to-node-assert"
                >Codemod Registry</a
              >.
            </p>
