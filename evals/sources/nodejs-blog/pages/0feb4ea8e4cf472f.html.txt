            <h1 id="nodejs-v20-to-v22"><a href="#nodejs-v20-to-v22">Node.js v20 to v22</a></h1>
            <div class="index-module__VYslka__alertBox index-module__VYslka__info">
              <span class="index-module__VYslka__title">!</span
              ><span class="index-module__VYslka__content"
                ><p>
                  This article covers a part of the migration from Node.js v20 to v22. The userland
                  migrations team is working on more codemods to help you with the migration.
                </p></span
              >
            </div>
            <p>
              This page provides a list of codemods to help you migrate your code from Node.js v20
              to v22.
            </p>
            <h2 id="import-assertions-to-attributes">
              <a href="#import-assertions-to-attributes"
                ><code>import-assertions-to-attributes</code></a
              >
            </h2>
            <p>
              During the process of TC39 standardization, the <code>import assert</code> feature was
              introduced to allow importing
              <a href="https://tc39.es/proposal-json-modules/">JSON modules</a>, but during the
              transition to stage 4, the <code>assert</code> keyword was replaced with the
              <code>with</code> attribute on the <code>import</code> statement.
            </p>
            <p>
              So in
              <a href="https://nodejs.org/fr/blog/release/v22.0.0#other-notable-changes"
                >node.js v22</a
              >, the <code>import assert</code> feature was removed and the
              <code>with</code> attribute is required instead.
            </p>
            <p>
              Also note that the <code>with</code> keyword was introduced in
              <a
                href="https://nodejs.org/fr/blog/release/v18.20.0#added-support-for-import-attributes"
                >node.js v18.20</a
              >
              but it was not mandatory until v22.
            </p>
            <p>
              The source code for this codemod can be found in the
              <a
                href="https://github.com/nodejs/userland-migrations/tree/main/recipes/import-assertions-to-attributes"
                >import-assertions-to-attributes directory</a
              >.
            </p>
            <p>
              You can find this codemod in the
              <a href="https://app.codemod.com/registry/@nodejs/import-assertions-to-attributes"
                >Codemod Registry</a
              >.
            </p>

            <h2 id="crypto-createcipheriv-migration">
              <a href="#crypto-createcipheriv-migration"
                ><code>crypto-createcipheriv-migration</code></a
              >
            </h2>
            <p>
              Migrates deprecated <code>crypto.createCipher()</code> /
              <code>crypto.createDecipher()</code> usage to the supported
              <code>crypto.createCipheriv()</code> / <code>crypto.createDecipheriv()</code> APIs
              with explicit key derivation and IV handling.
            </p>
            <p>
              Node.js removed <code>crypto.createCipher()</code> and
              <code>crypto.createDecipher()</code> in v22.0.0 (<a
                href="https://nodejs.org/api/deprecations.html#DEP0106"
                >DEP0106</a
              >). The legacy helpers derived keys with MD5 and no salt, and silently reused static
              IVs. This codemod replaces those calls with the modern, explicit APIs and scaffolds
              secure key derivation and IV management.
            </p>
            <p>
              The source code for this codemod can be found in the
              <a
                href="https://github.com/nodejs/userland-migrations/tree/main/recipes/crypto-createcipheriv-migration"
                >crypto-createcipheriv-migration directory</a
              >.
            </p>
            <p>
              You can find this codemod in the
              <a href="https://app.codemod.com/registry/@nodejs/crypto-createcipheriv-migration"
                >Codemod Registry</a
              >.
            </p>
            <div class="index-module__HWYciG__root">
              <pre
                class="index-module__HWYciG__content shiki shiki-themes github-light-default nord language-bash no-line-numbers no-footer"
                tabindex="0"
              ><code><span class="line"><span style="color:#953800;--shiki-dark:#88C0D0">npx</span><span style="color:#0A3069;--shiki-dark:#A3BE8C"> codemod</span><span style="color:#0A3069;--shiki-dark:#A3BE8C"> run</span><span style="color:#0A3069;--shiki-dark:#A3BE8C"> @nodejs/crypto-createcipheriv-migration</span></span></code></pre>
            </div>
            <h3 id="what-it-does"><a href="#what-it-does">What it does</a></h3>
            <ul>
              <li>
                Replaces invocations of <code>createCipher()</code> /
                <code>createDecipher()</code> with <code>createCipheriv()</code> /
                <code>createDecipheriv()</code>.
              </li>
              <li>
                Inserts scaffolding that derives keys with <code>crypto.scryptSync()</code> and
                generates random salts and IVs.
              </li>
              <li>
                Reminds developers to persist salt + IV for decryption and to adjust key/IV lengths
                per algorithm.
              </li>
              <li>
                Updates destructured imports to include the new helpers
                (<code>createCipheriv</code>, <code>createDecipheriv</code>,
                <code>randomBytes</code>, <code>scryptSync</code>).
              </li>
            </ul>
            <h3 id="example-1"><a href="#example-1">Example</a></h3>
            <div class="index-module__HWYciG__root">

<span class="line"><span style="color:#116329;--shiki-dark:#ECEFF4">+</span><span style="color:#116329;--shiki-dark:#A3BE8C"> const cipher = (() =&gt; {</span></span>

            <h3 id="important-notes"><a href="#important-notes">Important notes</a></h3>
            <ul>
              <li>
                The codemod cannot guarantee algorithm-specific key/IV sizes. Review the generated
                <code>scryptSync</code> length and IV length defaults and adjust as needed.
              </li>
              <li>
                Decryption snippets include placeholders (<code>Buffer.alloc(16)</code>) that must
                be replaced with the salt and IV stored during encryption.
              </li>
              <li>
                If your project already wraps key derivation logic, you may prefer to adapt the
                generated scaffolding to call existing helpers.
              </li>
              <li>
                The generated code is not backward-compatible and will be unable to decrypt data
                that was encrypted using <code>createCipher()</code>.
              </li>
              <li>
                The use of scrypt is one possible choice for deriving a key from a password, but you
                may wish to use Argon2id or PBKDF2 instead.
              </li>
            </ul>
