            <h2 id="security-releases-available">
              <a href="#security-releases-available">Security releases available</a>
            </h2>
            <p>
              Updates are now available for the 26.x, 24.x, 22.x Node.js release lines for the
              following issues.
            </p>
            <p>
              This security release includes the following dependency updates to address public
              vulnerabilities:
            </p>
            <ul>
              <li>undici (8.9.0, 7.29.0, 6.28.0) on 26.x, 24.x, 22.x</li>
              <li>llhttp (9.4.3) on 26.x, 24.x, 22.x</li>
            </ul>
            <h2
              id="http2-retained-headers-can-bypass-maxsessionmemory-limits-cve-2026-56846---high"
            >
              <a
                href="#http2-retained-headers-can-bypass-maxsessionmemory-limits-cve-2026-56846---high"
                >HTTP/2 retained headers can bypass <code>maxSessionMemory</code> limits
                (CVE-2026-56846) - (High)</a
              >
            </h2>
            <p>
              A flaw in Node.js HTTP/2 handling can let retained header blocks evade
              <code>maxSessionMemory</code> limits and cause remote memory exhaustion.
            </p>
            <p>Impact:</p>
            <ul>
              <li>This vulnerability affects all users in active release lines: 24.x, 22.x</li>
            </ul>
            <p>
              Thank you, to leduckhuong for reporting this vulnerability and thank you mcollina for
              fixing it.
            </p>
            <h2 id="http2-re-entrant-send-can-cause-heap-use-after-free-cve-2026-56848---high">
              <a href="#http2-re-entrant-send-can-cause-heap-use-after-free-cve-2026-56848---high"
                >HTTP/2 re-entrant send can cause heap-use-after-free (CVE-2026-56848) - (High)</a
              >
            </h2>
            <p>
              A flaw in Node.js HTTP/2 handling allows <code>nghttp2_session_mem_send()</code> to be
              called re-entrantly while <code>nghttp2_session_mem_recv()</code> is executing,
              resulting in a heap-use-after-free.
            </p>
            <p>Impact:</p>
            <ul>
              <li>
                This vulnerability affects all users in active release lines: 26.x, 24.x, 22.x
              </li>
            </ul>
            <p>
              Thank you, to hahahkim for reporting this vulnerability and thank you mcollina for
              fixing it.
            </p>
            <h2
              id="permission-model-path-matching-can-over-grant-filesystem-access-cve-2026-58043---high"
            >
              <a
                href="#permission-model-path-matching-can-over-grant-filesystem-access-cve-2026-58043---high"
                >Permission Model path matching can over-grant filesystem access (CVE-2026-58043) -
                (High)</a
              >
            </h2>
            <p>
              A flaw in Node.js Permission Model enforcement can over-grant filesystem access across
              radix-tree prefix boundaries.
            </p>
            <p>
              Under <code>--permission</code>, an attacker who is granted access to one path can
              abuse radix-tree prefix boundary handling to read from or write to paths outside the
              intended filesystem allowlist.
            </p>
            <p>Impact:</p>
            <ul>
              <li>
                This vulnerability affects all users in active release lines: 22.x, 24.x, 26.x
              </li>
            </ul>
            <p>
              Thank you, to sy2n0 for reporting this vulnerability and thank you RafaelGSS for
              fixing it.
            </p>
            <h2
              id="https-agent-can-reuse-mtls-identities-across-pfx-certificates-cve-2026-56850---medium"
            >
              <a
                href="#https-agent-can-reuse-mtls-identities-across-pfx-certificates-cve-2026-56850---medium"
                >HTTPS Agent can reuse mTLS identities across PFX certificates (CVE-2026-56850) -
                (Medium)</a
              >
            </h2>
            <p>
              A flaw in Node.js HTTPS Agent connection reuse can cause PFX object-array key
              collisions, allowing mutual TLS (mTLS) client identities to be reused across requests
              configured with different client certificates.
            </p>
            <p>Impact:</p>
            <ul>
              <li>
                This vulnerability affects all users in active release lines: 26.x, 24.x, 22.x
              </li>
            </ul>
            <p>
              Thank you, to yottt for reporting this vulnerability and thank you RafaelGSS for
              fixing it.
            </p>
            <h2
              id="https-agent-session-reuse-can-skip-hostname-verification-cve-2026-58040---medium"
            >
              <a
                href="#https-agent-session-reuse-can-skip-hostname-verification-cve-2026-58040---medium"
                >HTTPS Agent session reuse can skip hostname verification (CVE-2026-58040) -
                (Medium)</a
              >
            </h2>
            <p>
              An incomplete fix for CVE-2026-48934 has been identified in Node.js. HTTPS Agent TLS
              session reuse can skip hostname verification across identity policies.
            </p>
            <p>Impact:</p>
            <ul>
              <li>
                This vulnerability affects all users in active release lines: 26.x, 24.x, 22.x
              </li>
            </ul>
            <p>
              Thank you, to vnyuh for reporting this vulnerability and thank you mcollina for fixing
              it.
            </p>
            <h2
              id="nodesqlite-sqltagstore-iterator-replay-can-re-execute-writes-cve-2026-58041---medium"
            >
              <a
                href="#nodesqlite-sqltagstore-iterator-replay-can-re-execute-writes-cve-2026-58041---medium"
                ><code>node:sqlite</code> SQLTagStore iterator replay can re-execute writes
                (CVE-2026-58041) - (Medium)</a
              >
            </h2>
            <p>
              A flaw in <code>node:sqlite</code> allows a stale
              <code>StatementSyncIterator</code> created through
              <code>DatabaseSync#createTagStore()</code> to continue executing a cached prepared
              statement after it has been reset and rebound with new parameters.
              <code>SQLTagStore</code> resets cached statements using
              <code>sqlite3_reset()</code> directly, bypassing the iterator invalidation mechanism
              introduced for <code>StatementSync</code> in recent releases.
            </p>
            <p>Impact:</p>
            <ul>
              <li>This vulnerability affects all users in active release lines: 26.x, 24.x</li>
            </ul>
            <p>
              Thank you, to cantina-security for reporting this vulnerability and thank you mcollina
              for fixing it.
            </p>
            <h2
              id="dnsresolveany-can-abort-on-dns-responses-with-many-a-records-cve-2026-58042---medium"
            >
              <a
                href="#dnsresolveany-can-abort-on-dns-responses-with-many-a-records-cve-2026-58042---medium"
                ><code>dns.resolveAny()</code> can abort on DNS responses with many A records
                (CVE-2026-58042) - (Medium)</a
              >
            </h2>
            <p>
              A flaw in Node.js can cause <code>dns.resolveAny()</code> to abort the process when a
              DNS response contains more than 256 A records.
            </p>
            <p>Repeated triggering of this condition can lead to denial of service.</p>
            <p>Impact:</p>
            <ul>
              <li>
                This vulnerability affects all users in active release lines: 26.x, 24.x, 22.x
              </li>
            </ul>
            <p>
              Thank you, to cantina-security for reporting this vulnerability and thank you
              RafaelGSS for fixing it.
            </p>
            <h2
              id="nodezlib-sync-apis-can-crash-on-spoofed-typedarray-length-cve-2026-58045---medium"
            >
              <a
                href="#nodezlib-sync-apis-can-crash-on-spoofed-typedarray-length-cve-2026-58045---medium"
                ><code>node:zlib</code> sync APIs can crash on spoofed
                <code>TypedArray</code> length (CVE-2026-58045) - (Medium)</a
              >
            </h2>
            <p>
              A flaw in Node.js allows a spoofed <code>TypedArray</code> <code>byteLength</code> to
              trigger a reachable assertion in the synchronous <code>node:zlib</code> APIs, causing
              the process to crash.
            </p>
            <p>Repeated exploitation of this condition can result in a denial of service.</p>
            <p>Impact:</p>
            <ul>
              <li>
                This vulnerability affects all users in active release lines: 26.x, 24.x, 22.x
              </li>
            </ul>
            <p>
              Thank you, to byvini for reporting this vulnerability and thank you RafaelGSS for
              fixing it.
            </p>
            <h2
              id="permission-model-allows-trace-events-to-write-outside-the-allowlist-cve-2026-56847---low"
            >
              <a
                href="#permission-model-allows-trace-events-to-write-outside-the-allowlist-cve-2026-56847---low"
                >Permission Model allows trace events to write outside the allowlist
                (CVE-2026-56847) - (Low)</a
              >
            </h2>
            <p>
              A flaw in Node.js Permission Model enforcement allows
              <code>trace_events.createTracing().enable()</code> to write trace logs outside
              <code>--allow-fs-write</code> paths.
            </p>
            <p>
              This can lead to confidentiality impact or bypass of the intended security boundary
              under affected configurations.
            </p>
            <p>Impact:</p>
            <ul>
              <li>
                This vulnerability affects all users of the Permission Model in active release
                lines: 26.x, 24.x, 22.x
              </li>
            </ul>
            <p>
              Thank you, to 0xoroot for reporting this vulnerability and thank you RafaelGSS for
              fixing it.
            </p>
            <h2
              id="permission-model-allows-process-reports-to-write-outside-the-allowlist-cve-2026-58039---low"
            >
              <a
                href="#permission-model-allows-process-reports-to-write-outside-the-allowlist-cve-2026-58039---low"
                >Permission Model allows process reports to write outside the allowlist
                (CVE-2026-58039) - (Low)</a
              >
            </h2>
            <p>
              A flaw in Node.js Permission Model enforcement allows <code>process.report</code> to
              write and overwrite files outside <code>--allow-fs-write</code> paths.
            </p>
            <p>
              This can lead to confidentiality impact or bypass of the intended security boundary
              under affected configurations.
            </p>
            <p>Impact:</p>
            <ul>
              <li>
                This vulnerability affects all users in active release lines: 26.x, 24.x, 22.x
              </li>
            </ul>
            <p>
              Thank you, to sinan-polat for reporting this vulnerability and thank you RafaelGSS for
              fixing it.
            </p>
            <h2
              id="http-parser-header-truncation-can-enable-request-smuggling-cve-2026-58044---low"
            >
              <a
                href="#http-parser-header-truncation-can-enable-request-smuggling-cve-2026-58044---low"
                >HTTP parser header truncation can enable request smuggling (CVE-2026-58044) -
                (Low)</a
              >
            </h2>
            <p>
              A flaw in Node.js HTTP client can cause a request desynchronization for Node.js-based
              forwarding proxies that rebuild outbound headers from the visible
              <code>IncomingMessage</code> headers while piping the original body to a reused
              backend connection.
            </p>
            <p>
              Node.js can omit headers beyond <code>maxHeadersCount</code> /
              <code>maxHeaderPairs</code> from <code>req.headers</code>,
              <code>req.rawHeaders</code>, and <code>req.headersDistinct</code>, while still using
              those omitted headers internally for HTTP message framing. In particular,
              <code>Content-Length</code> can be hidden from userland while the request body is
              still delivered.
            </p>
            <p>Impact:</p>
            <ul>
              <li>
                This vulnerability affects all users in active release lines: 26.x, 24.x, 22.x
              </li>
            </ul>
            <p>
              Thank you, to yushengchen for reporting this vulnerability and thank you mcollina for
              fixing it.
            </p>
