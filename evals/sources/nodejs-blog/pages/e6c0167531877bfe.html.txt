            <h2 id="security-releases-available">
              <a href="#security-releases-available">Security releases available</a>
            </h2>
            <p>
              Updates are now available for the 24.x, 22.x, 20.x Node.js release lines for the
              following issues.
            </p>
            <h2
              id="windows-device-names-con-prn-aux-bypass-path-traversal-protection-in-pathnormalize-cve-2025-27210---high"
            >
              <a
                href="#windows-device-names-con-prn-aux-bypass-path-traversal-protection-in-pathnormalize-cve-2025-27210---high"
                >Windows Device Names (CON, PRN, AUX) Bypass Path Traversal Protection in
                path.normalize() (CVE-2025-27210) - (high)</a
              >
            </h2>
            <p>
              An incomplete fix has been identified for CVE-2025-23084 in Node.js, specifically
              affecting Windows device names like CON, PRN, and AUX.
            </p>
            <p>This vulnerability affects Windows users of <code>path.join</code> API.</p>
            <p>Impact:</p>
            <ul>
              <li>
                This vulnerability affects all users in active release lines: 20.x, 22.x, 24.x
              </li>
            </ul>
            <p>
              Thank you, to oblivionsage for reporting this vulnerability and thank you RafaelGSS
              for fixing it.
            </p>
            <h2 id="hashdos-in-v8-cve-2025-27209---high">
              <a href="#hashdos-in-v8-cve-2025-27209---high"
                >HashDoS in V8 (CVE-2025-27209) - (high)</a
              >
            </h2>
            <p>
              The V8 release used in Node.js v24.0.0 has changed how string hashes are computed
              using rapidhash. This implementation re-introduces the HashDoS vulnerability as an
              attacker who can control the strings to be hashed can generate many hash collisions -
              an attacker can generate collisions even without knowing the hash-seed.
            </p>
            <p>
              While the V8 team does not classify this as a security vulnerability, the Node.js
              project considers it one due to its potential impact in real-world scenarios.
            </p>
            <ul>
              <li>This vulnerability affects Node.js v24.x users.</li>
            </ul>
            <p>Impact:</p>
            <ul>
              <li>This vulnerability affects all users in active release lines: 24.x</li>
            </ul>
            <p>
              Thank you, to sharp_edged for reporting this vulnerability and thank you targos for
              fixing it.
            </p>

            <h1 id="summary"><a href="#summary">Summary</a></h1>
            <p>
              The Node.js project will release new versions of the 24.x, 22.x, 20.x releases lines
              on or shortly after, Tuesday, July 15, 2025 in order to address:
            </p>
            <ul>
              <li>2 high severity issues.</li>
            </ul>
            <h2 id="impact"><a href="#impact">Impact</a></h2>
            <p>
              The 24.x release line of Node.js is vulnerable to 2 high severity issues. The 22.x
              release line of Node.js is vulnerable to 1 high severity issues. The 20.x release line
              of Node.js is vulnerable to 1 high severity issues.
            </p>
            <p>
              It&#x27;s important to note that End-of-Life versions are always affected when a
              security release occurs. To ensure your system&#x27;s security, please use an
              up-to-date version as outlined in our
              <a href="https://github.com/nodejs/release#release-schedule">Release Schedule</a>.
            </p>
            <h2 id="release-timing"><a href="#release-timing">Release timing</a></h2>
            <p>Releases will be available on, or shortly after, Tuesday, July 15, 2025.</p>
