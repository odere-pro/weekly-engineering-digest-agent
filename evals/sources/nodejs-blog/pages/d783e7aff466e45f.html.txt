            <h3 id="notable-changes"><a href="#notable-changes">Notable Changes</a></h3>
            <h4 id="upgrade-to-openssl-35">
              <a href="#upgrade-to-openssl-35">Upgrade to OpenSSL 3.5</a>
            </h4>
            <p>
              This release is distributed with OpenSSL 3.5.1, following the announcement that
              OpenSSL 3.5 will be supported until April 2030, while Node.js 24 will be supported
              until April 2028. Read more about OpenSSL support in their blog post:
              <a href="https://openssl-library.org/post/2025-02-20-openssl-3.5-lts/"
                >https://openssl-library.org/post/2025-02-20-openssl-3.5-lts/</a
              >.
            </p>
            <p>
              Contributed by Richard Lau in
              <a href="https://github.com/nodejs/node/pull/58100">#58100</a>.
            </p>
            <h4 id="unflag---experimental-wasm-modules">
              <a href="#unflag---experimental-wasm-modules"
                >Unflag <code>--experimental-wasm-modules</code></a
              >
            </h4>
            <p>
              Node.js supports both source phase imports and instance phase imports to WebAssembly
              modules and for WASM imports to JavaScript, in line with the current Phase 3
              WebAssembly
              <a href="https://github.com/webassembly/esm-integration">ESM Integration</a> proposal.
              The implementation and the specification are still subject to change.
            </p>
            <p>
              Contributed by Guy Bedford in
              <a href="https://github.com/nodejs/node/pull/57038">#57038</a>.
            </p>
            <h4 id="built-in-proxy-support-in-request-and-agent">
              <a href="#built-in-proxy-support-in-request-and-agent"
                >Built-in proxy support in <code>request()</code> and <code>Agent</code></a
              >
            </h4>
            <p>
              <code>node:http</code> and <code>node:https</code> now support proxies. When
              <code>NODE_USE_ENV_PROXY</code> is set to <code>1</code>, the default global agent
              would parse the <code>http_proxy</code>/<code>HTTP_PROXY</code>,
              <code>https_proxy</code>/<code>HTTPS_PROXY</code>, <code>no_proxy</code>/<code
                >NO_PROXY</code
              >
              settings from the environment variables, and proxy the requests sent through the
              built-in http/https client accordingly.
            </p>
            <p>To use global proxy support from the command line:</p>

            <h4 id="add-setdefaultcacertificates-to-nodetls">
              <a href="#add-setdefaultcacertificates-to-nodetls"
                >Add <code>setDefaultCACertificates()</code> to <code>node:tls</code></a
              >
            </h4>
            <p>
              This API allows dynamically configuring CA certificates that will be used by the
              Node.js TLS clients by default.
            </p>
            <p>
              Once called, the provided certificates will become the default CA certificate list
              returned by <code>tls.getCACertificates(&#x27;default&#x27;)</code> and used by TLS
              connections that don&#x27;t specify their own CA certificates.
            </p>
            <p>
              To add system CA certificates to the default bundle (which includes the Mozilla CA
              certificates):
